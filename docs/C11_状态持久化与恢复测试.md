## 5.1 落盘路径与文件职责（B11 §4）

```
<StarTools.get_data_dir()>/            # 容器内 /AstrBot/data/plugin_data/astrbot_plugin_guardian
└── guardian/
    ├── state.json                  # 主状态：mode/profile/night_until/cooldown/circuit/last_status/seq
    ├── state.json.tmp.<pid>        # 原子写临时文件（瞬态，写后立即 os.replace）
    ├── state.json.corrupt.<ts>     # 损坏备份（保留待人工分析）
    ├── samples.json (+ .corrupt.<ts>)   # 内存采样窗口与损坏备份（B06）
    ├── audit.jsonl                 # 追加式审计（当前）
    ├── audit.jsonl.1 … .3          # 轮转备份（.1 最新，.3 最旧）
    └── memory_snapshots_<c>.json   # 重启前快照（B06，由动作层写入）
```

**判据**：任何"重启后行为应保持一致"的状态必须落盘；任何"重启后重新计算即可"的状态不得落盘（避免写放大）。两种路径均**不落在插件源码目录**（D5，C11-07）。

## 5.2 崩溃点分析（B11 §8）

| 崩溃点 | 后果 | 兜底 | 用例 |
| --- | --- | --- | --- |
| `_touch` 之后、`save` 之前 | 内存改动丢失（≤ flush_interval 秒） | 关键动作立即 `save()` | C11-24 |
| 写 `tmp` 中途 | 临时文件不完整 | 下次启动忽略 `*.tmp.*` | C11-11/27 |
| `os.replace` 中途 | 由文件系统保证原子性 | 旧/新二者其一 | C11-28 |
| 两文件之间 / KV 镜像前 | `seq` 不一致 / KV 陈旧 | 各自独立加载，下次 `save` 补齐 | C11-29 |

## 5.3 KV 与文件收敛规则（B11 §7）

| 维度 | KV（`get_kv_data`/`put_kv_data`） | 文件（`data/guardian/*.json*`） |
| --- | --- | --- |
| 适合 | 少量关键标量：`mode`/`profile`/`night_until` | 大结构：冷却/熔断/采样/事件历史 |
| 权威性 | **镜像**（缓存） | **权威（source of truth）** |
| 收敛 | ① 正常路径只写文件，成功后镜像 KV；② 文件缺失时由 KV 播种；③ 不一致时**文件优先**；④ KV 异常仅告警 | C11-19/20/23 |
