# B08 · 告警、通知与事件总线

> 上位规格：B00《项目总览与需求规格》v0.1.0。实现 B00 §3.2（数据流）、§5（档位静默）、§7（`notify.*` 契约）、§13（Gate `G-INSTALL` / `G-STABILITY`）。关联 B03（探针）、B07（ROS2）、B11（状态与审计）、B12（安全）、C08（测试）。

## 1. 目标

| ID | 目标 | 判据 |
| --- | --- | --- |
| N-G1 | 一次巡检的结果能可靠送达会话 | `notify.umo_list` 中每个有效 UMO 收到一条聚合消息 |
| N-G2 | 不刷屏 | 同目标同状态在 `notify.rate_limit_sec` 窗口内只推一次 |
| N-G3 | 只在状态跃迁时告警 | `OK→CRIT` 告警、`CRIT→CRIT` 静默、`CRIT→OK` 发恢复通知 |
| N-G4 | 档位可静默 | `night` 静默低于 `night_profile.mute_below_severity`；`maintenance` 全静默 |
| N-G5 | 推送失败不拖垮引擎 | 异常被吞并降级到日志，巡检主流程零中断 |
| N-G6 | 每次通知可追溯 | 每次投递（含被抑制）写审计 |
| N-G7 | 探针与通知解耦 | 探针只发事件，不认识 UMO / 消息模板 |

## 2. `core/bus.py` 与 `notify/notifier.py` 的职责边界

| 维度 | `core/bus.py` | `notify/notifier.py` |
| --- | --- | --- |
| 定位 | 进程内异步 pub/sub，**零业务语义** | 通知策略与投递，**全部业务语义** |
| 输入 | `(topic: str, payload: Any)` | `Incident` 列表（由 bus 事件触发） |
| 输出 | 调用订阅者协程，返回成功数 | 经 `context.send_message` 推送文本 |
| 认识 AstrBot? | 否（不 import astrbot） | 是（context / MessageChain / UMO） |
| 认识配置? | 否 | 是（`notify.*`、档位静默） |
| 失败策略 | 订阅者异常隔离 + 计数 | 重试、降级日志、UMO 失效标记 |
| 可单测性 | 纯 asyncio，无外部依赖 | 注入 fake context 即可测（C08） |

**主题清单**（发布方 → 订阅方）：

| 主题 | 发布方 → 主要订阅方 |
| --- | --- |
| `engine.tick` / `probe.result` / `policy.finding` | `HealthEngine` / 探针 / `PolicyEngine` → 审计、诊断缓存 |
| `safety.denied` / `safety.circuit_open` | `SafetyGuard.authorize` → 通知（升级告警）、审计 |
| `action.result` | 动作层 → 审计、通知（动作回执） |
| `incident.recorded` | `StateStore.record_incident` → **通知**、审计 |
| `notify.sent` / `notify.failed` | Notifier → 审计、指标 |
| `profile.changed` / `mode.changed` | 命令与工具层 → 通知（切换回执） |
| `plugin.started` / `plugin.stopped` | `main.py` 生命周期 → 通知（上下线通知） |

## 3. `core/bus.py`（完整代码）

```python
# core/bus.py
"""进程内异步事件总线：解耦探针/引擎与通知、审计、指标订阅者。

设计约束（B00 D4/D9）：
  * 零业务语义，不 import astrbot，可脱离框架单测；
  * 订阅者异常严格隔离：一个 handler 崩溃不得影响巡检主流程；
  * 全部 await，禁止在 publish 中做阻塞 IO。
"""
from __future__ import annotations
import asyncio, fnmatch, logging
from collections import defaultdict
from typing import Any, Awaitable, Callable

Handler = Callable[[str, Any], Awaitable[None]]

TOPICS = ("engine.tick", "probe.result", "policy.finding", "action.result",
          "incident.recorded", "notify.sent", "notify.failed", "safety.denied",
          "safety.circuit_open", "profile.changed", "mode.changed",
          "plugin.started", "plugin.stopped")


class EventBus:
    def __init__(self, logger=None) -> None:
        self.log = logger or logging.getLogger("guardian.bus")
        self._subs: dict[str, list[Handler]] = defaultdict(list)
        self._stats = {"published": 0, "delivered": 0, "failed": 0}

    def subscribe(self, pattern: str, handler: Handler) -> None:
        """pattern 支持 fnmatch 通配，如 "notify.*"（同前缀）或 "*"（全部）。"""
        self._subs[pattern].append(handler)

    def unsubscribe(self, pattern: str, handler: Handler) -> None:
        if handler in self._subs.get(pattern, []):
            self._subs[pattern].remove(handler)

    def clear(self) -> None:
        """terminate() 时清空，防止热重载后旧订阅者残留（B00 R10）。"""
        self._subs.clear()

    def _handlers(self, topic: str) -> list[Handler]:
        out: list[Handler] = []
        for pattern, handlers in self._subs.items():
            if pattern == topic or fnmatch.fnmatchcase(topic, pattern):
                out.extend(handlers)
        return out

    async def publish(self, topic: str, payload: Any = None) -> int:
        """并发投递，返回成功订阅者数；任何异常都被吞掉并计入 failed。"""
        self._stats["published"] += 1
        handlers = self._handlers(topic)
        if not handlers:
            return 0
        results = await asyncio.gather(*(self._safe(topic, h, payload) for h in handlers))
        ok = sum(1 for r in results if r)
        self._stats["delivered"] += ok
        self._stats["failed"] += len(results) - ok
        return ok

    async def _safe(self, topic: str, handler: Handler, payload: Any) -> bool:
        try:
            await handler(topic, payload)
            return True
        except asyncio.CancelledError:
            raise                      # 取消必须向上传播，否则定时器无法收敛
        except Exception as e:         # noqa: BLE001 订阅者隔离（B00 D4）
            self.log.error("订阅者 %s 处理 %s 失败: %s",
                           getattr(handler, "__qualname__", handler), topic, e, exc_info=True)
            return False
```

## 4. `notify/notifier.py`（完整代码）

```python
# notify/notifier.py
"""通知分发：级别过滤 → 档位静默 → 状态跃迁 → 限流去重 → 聚合渲染 → 推送（带重试与降级）。"""
from __future__ import annotations
import time
from astrbot.api.message_components import Plain
from ..core.models import Incident, Severity, Status

SEV_ORDER = {Severity.INFO: 0, Severity.WARN: 1, Severity.CRIT: 2, Severity.FATAL: 3}
MAX_SEND_RETRIES = 2
UMO_FAIL_THRESHOLD = 3          # 连续失败 N 次后标记 UMO 失效


class Notifier:
    def __init__(self, context, cfg, bus, audit, state, logger) -> None:
        self.context, self.cfg, self.bus = context, cfg, bus
        self.audit, self.state, self.log = audit, state, logger
        self._last_status: dict[str, str] = {}      # key -> 上次状态值（跃迁判定）
        self._recent: dict[str, float] = {}         # dedup key -> 上次推送 ts
        self._umo_fail: dict[str, int] = {}         # UMO -> 连续失败次数

    async def start(self) -> None:
        self.bus.subscribe("incident.recorded", self._on_incident)
        self.bus.subscribe("profile.changed", self._on_profile)
        self.bus.subscribe("mode.changed", self._on_mode)
        self.bus.subscribe("plugin.started", self._on_lifecycle)
        self.bus.subscribe("plugin.stopped", self._on_lifecycle)
        self.bus.subscribe("safety.circuit_open", self._on_incident)

    # ---------- 事件入口 ----------
    async def _on_incident(self, topic: str, payload) -> None:
        items = payload if isinstance(payload, (list, tuple)) else [payload]
        await self.dispatch([i for i in items if isinstance(i, Incident)])

    async def _on_profile(self, topic: str, payload) -> None:
        await self._push_raw("档位切换", "已切换守护档位为 %s" % getattr(payload, "value", payload))

    async def _on_mode(self, topic: str, payload) -> None:
        await self._push_raw("模式切换", "已切换守护模式为 %s" % getattr(payload, "value", payload))

    async def _on_lifecycle(self, topic: str, payload) -> None:
        await self._push_raw("生命周期", "Guardian %s（档位 %s / 模式 %s）"
                             % ("已启动" if topic == "plugin.started" else "已停止",
                                getattr(payload, "profile", "?"), getattr(payload, "mode", "?")))

    # ---------- 主流程 ----------
    async def dispatch(self, incidents: list[Incident]) -> int:
        """一次巡检的多个 Incident 聚合为一条消息，避免刷屏（B00 R8）。"""
        if not incidents:
            return 0
        keep: list[Incident] = []
        for inc in incidents:
            ok, reason = self._pass_filter(inc)
            if not ok:
                inc.suppressed, inc.suppress_reason = True, reason
                await self._audit("notify.skipped", inc, reason)
                continue
            keep.append(inc)
        if not keep:
            return 0
        text = self.render(keep)
        sent = 0
        for umo in self._targets():
            if await self._send(umo, text):
                sent += 1
        for inc in keep:
            inc.notified = sent > 0
            await self._audit("notify.sent" if sent else "notify.failed", inc,
                              "umo_ok=%d" % sent)
        await self.bus.publish("notify.sent" if sent else "notify.failed",
                               {"count": len(keep), "umo_ok": sent})
        return sent

    def _pass_filter(self, inc: Incident) -> tuple[bool, str]:
        """返回 (是否推送, 抑制原因)。顺序：档位静默 → 级别 → 跃迁 → 限流去重。"""
        profile = str(self.cfg.get("profile", "normal"))
        if profile == "maintenance":
            return False, "profile_maintenance_mutes_all"
        min_sev = Severity(str(self.cfg.get("notify.min_severity", "warn")))
        if SEV_ORDER[inc.severity] < SEV_ORDER[min_sev]:
            return False, "below_min_severity"
        if profile == "night":
            mute = Severity(str(self.cfg.get("night_profile.mute_below_severity", "warn")))
            if SEV_ORDER[inc.severity] < SEV_ORDER[mute]:
                return False, "night_mute"
        if not self._transition(inc):
            return False, "no_state_transition"
        key = "%s|%s|%s" % (inc.probe, inc.target, inc.status.value)
        window = int(self.cfg.get("notify.rate_limit_sec", 60))
        now = time.time()
        if now - self._recent.get(key, 0.0) < window:
            return False, "rate_limited"
        self._recent[key] = now
        return True, ""

    def _transition(self, inc: Incident) -> bool:
        """只在状态跃迁时告警：OK->CRIT 告警；CRIT->CRIT 不重复；CRIT->OK 发恢复。"""
        key = "%s|%s" % (inc.probe, inc.target)
        prev = self._last_status.get(key)
        cur = inc.status.value
        self._last_status[key] = cur
        if prev is None:
            return cur != Status.OK.value        # 首次出现且非 OK 才告警
        if prev == cur:
            return False
        return True                              # 任意方向跃迁都值得说一次

    # ---------- 渲染 ----------
    def render(self, incidents: list[Incident]) -> str:
        if len(incidents) == 1:
            return self._render_one(incidents[0])
        head = "Guardian 巡检摘要（%d 项，%s）" % (len(incidents), time.strftime("%m-%d %H:%M:%S"))
        lines = [head]
        for inc in incidents:
            lines.append("· [%s] %s/%s %s" % (inc.severity.value.upper(), inc.probe,
                                              inc.target, inc.message))
        act = [i for i in incidents if i.action]
        if act:
            lines.append("动作: %s" % "；".join(
                "%s(%s)=%s" % (i.action.kind, i.action.target,
                               "ok" if (i.result and i.result.ok) else "fail") for i in act))
        return "\n".join(lines)

    def _render_one(self, inc: Incident) -> str:
        status = "已恢复" if inc.status is Status.OK else inc.status.value.upper()
        body = "[%s] %s/%s %s\n%s" % (inc.severity.value.upper(), inc.probe, inc.target,
                                      status, inc.message)
        if inc.action:
            res = inc.result
            body += "\n动作: %s(%s) -> %s%s" % (inc.action.kind, inc.action.target,
                                               "成功" if res and res.ok else "失败",
                                               ("，%s" % res.detail) if res else "")
        if inc.suppressed:
            body += "\n已抑制: %s" % inc.suppress_reason
        return body

    async def _push_raw(self, title: str, body: str) -> int:
        sent = 0
        for umo in self._targets():
            if await self._send(umo, "%s\n%s" % (title, body)):
                sent += 1
        return sent

    # ---------- 投递 ----------
    def _targets(self) -> list[str]:
        return [u for u in (self.cfg.get("notify.umo_list", []) or [])
                if u and self._umo_fail.get(u, 0) < UMO_FAIL_THRESHOLD]

    async def _send(self, umo: str, text: str) -> bool:
        """推送失败重试 MAX_SEND_RETRIES 次，最终降级到日志（B00 §10 可观测性）。"""
        for attempt in range(1, MAX_SEND_RETRIES + 1):
            try:
                await self.context.send_message(umo, MessageChain().message(text))
                self._umo_fail[umo] = 0
                return True
            except Exception as e:            # noqa: BLE001 通知绝不向上抛
                self.log.warning("推送失败(%d/%d) umo=%s: %s", attempt, MAX_SEND_RETRIES, umo, e)
        self._umo_fail[umo] = self._umo_fail.get(umo, 0) + 1
        if self._umo_fail[umo] >= UMO_FAIL_THRESHOLD:
            self.log.error("UMO %s 连续失败 %d 次，标记失效并暂停推送",
                           umo, self._umo_fail[umo])
            await self.audit.append(kind="notify.umo_invalid", target=umo,
                                    detail="consecutive_failures=%d" % self._umo_fail[umo])
        self.log.error("[降级] 通知未送达 umo=%s:\n%s", umo, text)
        return False

    async def _audit(self, kind: str, inc: Incident, detail: str) -> None:
        await self.audit.append(kind=kind, target="%s/%s" % (inc.probe, inc.target),
                                detail="%s; %s" % (inc.message, detail), incident_id=inc.id)
```

## 5. 消息模板设计

四类模板固定为「首行结论 + 明细 + 动作/抑制」，便于 QQ 侧一眼扫读。

| 模板 | 触发 | 关键字段 |
| --- | --- | --- |
| 健康快照 | `/guardian status`、`guardian_health_report` | 容器/内存/QQ/ROS2 各一行 |
| 事件告警 | `incident.recorded`（单条） | severity、probe/target、status、message、action |
| 动作回执 | `action.result` / Incident 带 result | kind、target、成功/失败、detail、elapsed_ms |
| 启动/停止 | `plugin.started` / `plugin.stopped` | profile、mode、探针数 |

**实际渲染示例**

```
[CRIT] container_health/napcat CRIT
容器未在运行（status=exited, exit_code=1）
动作: restart_container(napcat) -> 成功，已拉起，耗时 1840ms
```

```
Guardian 巡检摘要（3 项，10-13 04:00:12）
· [CRIT] ros2_nodes//camera_node 节点缺失（期望存在但未发现）
· [WARN] ros2_topics//scan 话题频率偏低: 2.100 Hz < 5.000 Hz
· [WARN] container_memory/astrbot 内存 745MB 超过告警阈值 700MB
动作: ros2_restart(/camera_node)=ok
```

```
生命周期
Guardian 已启动（档位 night / 模式 server）
```

恢复通知（`CRIT → OK` 跃迁，最容易被忽略但最有价值的一类）：`[INFO] container_health/napcat 已恢复 / 容器运行中（uptime 42s）`。
## 6. 告警聚合

一次巡检可能同时产出多条 Finding（如容器挂掉 + 内存超阈 + 话题静默）。聚合规则：

1. `HealthEngine.run_once` 收集本轮全部 `Incident`，**一次性**交给 `Notifier.dispatch(list)`。
2. `dispatch` 先做过滤，再**一条消息**渲染所有通过过滤的事件（`render()` 的 `len>1` 分支）。
3. 动作回执不单独成消息，而是折进摘要末行 `动作: kind(target)=ok|fail`。
4. 单轮推送总量上限为 1 条消息 × `len(有效 UMO)`，与事件数无关——这是「不刷屏」的结构性保证，比单纯限流更可靠。

```
run_once() 产出 [inc1, inc2, inc3]
  └─ Notifier.dispatch([...])
       ├─ 过滤: inc1 通过 / inc2 night_mute / inc3 rate_limited
       ├─ render([inc1])           → 1 条文本
       └─ for umo in targets: _send(umo, text)     → 每 UMO 恰好 1 条
```

## 7. 去重与状态跃迁

`_last_status[(probe,target)]` 保存上次状态，`_recent[(probe,target,status)]` 保存上次推送时间。

| 跃迁 | 推送 | 理由 |
| --- | --- | --- |
| `None → OK` | 否 | 首次基线，无需告警 |
| `None → CRIT` | 是 | 启动即发现故障，必须说 |
| `OK → CRIT` | 是 | 核心告警路径 |
| `CRIT → CRIT` | 否 | 同状态不重复（配合 rate_limit 双保险） |
| `CRIT → WARN` / `WARN → OK` | 是 | 好转但仍异常 / 恢复，均需闭环提示 |
| `CRIT → OK` | 是 | 恢复通知（避免「报过就不管」） |

```
incident(status=CRIT) ─▶ _transition()
   prev=None  ─▶ True（CRIT）─▶ dedup(rate_limit) ─▶ 推送
   prev=CRIT  ─▶ False        ─▶ 抑制(no_state_transition)，写审计
   prev=OK    ─▶ True（CRIT）─▶ 推送
incident(status=OK)   ─▶ prev=CRIT ─▶ True ─▶ 推送「已恢复」
```

**重启后状态恢复**：`_last_status` 落盘到 `StateStore`（键 `notify:last_status`），插件重启后不因基线丢失而重放一遍全量告警。

## 8. 档位与静默

| 档位 | 巡检 | 通知策略 | 实现位置 |
| --- | --- | --- | --- |
| `normal` | 60s | 按 `notify.min_severity`（默认 `warn`） | `_pass_filter` 级别分支 |
| `night` | 180s | 额外静默低于 `night_profile.mute_below_severity`（默认 `warn`）的告警 | `_pass_filter` night 分支 |
| `maintenance` | 暂停 | **全静默**（连 FATAL 也不推，只写审计与日志） | `_pass_filter` 首行短路 |
| `aggressive` | 20s | 同 `normal`，但阈值更敏感、限流窗口建议调大 | 配置侧 |

被静默的事件**不丢弃**：仍写入 `Incident.suppressed=True` + `suppress_reason` 并落审计，`/guardian incidents` 与 `guardian_list_incidents` 仍可查到，保证「静默 ≠ 失明」。

## 9. 严重级别与推送渠道矩阵

| Severity | normal | night | maintenance | 渠道 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `INFO` | 否（默认 min=warn） | 否 | 否 | 日志 + 审计 | 恢复通知若需推送可把 `min_severity` 调为 `info` |
| `WARN` | 是 | 是 | 否 | UMO | 频率偏低、内存超告警阈 |
| `CRIT` | 是 | 是 | 否 | UMO + 动作回执 | 容器退出、节点缺失、话题静默 |
| `FATAL` | 是 | 是 | 否 | UMO + 审计升级 | 熔断、连续动作失败、重登失败 |

本期推送渠道仅 `context.send_message`（QQ 会话）。`notify.umo_list` 为空时，所有通知降级为日志，**不视为错误**（首次部署常见状态），但启动自检会给出 `WARN` 提示。

## 10. 与 LLM 工具的关系

| 场景 | 路径 | 说明 |
| --- | --- | --- |
| 用户问「现在怎么样」 | `guardian_health_report` → `engine.snapshot()` | **直接读引擎快照**，不经 Notifier、不推送、不写 `notify.sent` |
| 用户要求立即巡检 | `guardian_run_check` → `engine.run_once(trigger="llm")` | 巡检产生的 Incident 走正常通知链（可能触发推送） |
| 用户查历史 | `guardian_list_incidents` → `StateStore` | 只读，不受静默/限流影响 |
| 进入夜间 | `guardian_enter_night_watch` | 切档位后由 `profile.changed` 事件推送回执 |

**关键点**：`guardian_health_report` 必须绕过通知层。若让它复用 Notifier，会污染 `_last_status` 跃迁基线并触发 `rate_limit`，导致真实告警被限流吞掉。

## 11. 通知的可靠性

| 风险 | 处理 |
| --- | --- |
| `send_message` 抛异常（网络/适配器） | `_send` 内 `try/except`，重试 `MAX_SEND_RETRIES=2` 次，仍失败则 `log.error` 输出全文（降级不丢内容） |
| UMO 失效（群解散/被踢/适配器重载） | 连续失败 `UMO_FAIL_THRESHOLD=3` 次标记失效，`_targets()` 自动跳过，写 `notify.umo_invalid` 审计 |
| 全部 UMO 失效 / 消息过长 / 通知风暴 | 推送计数为 0 且 `incident.notified=False`（不影响巡检）；`raw` 截断 2000 字符；每轮 ≤1 条 × UMO 数 + `rate_limit_sec` |
| 事件循环阻塞 | `_send` 全程 await，无同步 IO；聚合渲染为纯字符串拼接（B00 D9） |

```
_send(umo, text)
  ├─ attempt 1 → ok   → 清零失败计数, return True
  ├─ attempt 1 → fail → log.warning
  ├─ attempt 2 → ok   → 清零, return True
  └─ attempt 2 → fail → 计数+1
        ├─ 计数 < 3  → log.error("[降级] 全文") + return False
        └─ 计数 >= 3 → audit(notify.umo_invalid) + 后续跳过该 UMO
```

## 12. 审计联动

| 审计 kind | 触发点 | 关键字段 |
| --- | --- | --- |
| `notify.sent` | 至少一个 UMO 成功 | `target=probe/target`、`detail=umo_ok=N`、`incident_id` |
| `notify.failed` | 全部 UMO 失败 | 同上 + 最后一条异常摘要 |
| `notify.skipped` | 被过滤/静默/限流 | `detail=suppress_reason`（如 `night_mute`） |
| `notify.umo_invalid` | UMO 连续失败达阈值 | `target=umo`、`detail=consecutive_failures=N` |

审计不可关（B00 §10-7）：即使 `maintenance` 全静默，`notify.skipped` 仍逐条落盘，事后可复盘「当时为什么没告警」。

## 13. 验收标准（对应 C08）

| # | 验收项 | 方法 | 判据 | 关联 |
| --- | --- | --- | --- | --- |
| B1 | 订阅者隔离 | 注册一个必抛异常的 handler，再发 `probe.result` | `publish` 正常返回，异常 handler 计 `failed`，其他 handler 收到 | N-G7 |
| B2 | 通配主题 | 订阅 `notify.*`，发 `notify.sent` / `notify.failed` | 两次都被调用 | §2 |
| B3 | 基础推送 | 单条 CRIT Incident，`umo_list` 配 1 个有效 UMO | 收到 1 条含 severity/probe/target/message 的消息 | N-G1 |
| B4 | 聚合 | 一轮产出 3 条 Incident | 只收到 1 条摘要消息，含 3 个 `·` 行 | §6 |
| B5 | 跃迁 | 依次注入 `CRIT`、`CRIT`、`OK` | 收到 2 条：告警 + 恢复通知 | N-G3 |
| B6 | 限流 | 1s 内连续两轮同目标同状态（先造跃迁） | 第二条被 `rate_limited` 抑制，审计有记录 | N-G2 |
| B7 | 级别过滤 | `min_severity=crit`，注入 `WARN` | 不推送，`suppress_reason=below_min_severity` | §9 |
| B8 | 夜间静默 | `profile=night`，注入 `INFO` | 不推送，`suppress_reason=night_mute` | N-G4 |
| B9 | 维护静默 | `profile=maintenance`，注入 `FATAL` | 不推送，`suppress_reason=profile_maintenance_mutes_all` | N-G4 |
| B10 | 失败降级 | fake context 抛异常 | 引擎不中断，日志含全文，`incident.notified=False` | N-G5 |
| B11 | UMO 失效 | 让同一 UMO 连续失败 3 轮 | 第 4 轮起该 UMO 被跳过，有 `notify.umo_invalid` 审计 | §11 |
| B12 | 只读工具不污染 | 调 `guardian_health_report` 数次 | `_last_status` 不变，无 `notify.sent` 审计 | §10 |
| B13 | 审计与热重载 | 跑完上述用例后 `terminate()` | 每条 Incident 至少 1 条 `notify.*` 审计；`bus.clear()` 后旧订阅者不再被调用 | N-G6 / B00 R10 |

**Gate 复述**：`G-INSTALL` 要求启动后 `/guardian status` 有响应且无异常日志——对应 B3/B10；`G-STABILITY` 要求 72h 无刷屏与无事件循环阻塞——对应 B4/B6/B10。
