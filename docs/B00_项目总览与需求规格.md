## 1. 背景与目标

### 1.1 背景
AstrBot 以「AstrBot 本体容器 + NapCat 协议端容器」双容器方式部署在 Arch Linux 上。长期无人值守运行时会出现典型故障：

1. QQ 被踢下线 / 登录失效 → Bot 静默失联，无人发现。
2. 容器长时间运行内存缓慢增长（内存泄漏）→ 最终 OOM 被杀，服务中断。
3. 容器崩溃退出后没有自愈，需要人工介入。
4. ROS2 场景下节点/话题挂掉，业务链路中断。
5. 运维只能靠人肉 `docker logs` / `docker stats`，缺少统一健康视图。
6. Bot 无法参与运维：用户想「让它自己管好自己」却没有任何工具接口。

### 1.2 目标
- **G1 自愈**：协议端掉线自动重登、容器异常自动拉起、泄漏自动重启。
- **G2 可观测**：统一健康快照（容器状态、内存、QQ 在线、ROS2 节点/话题），可查询、可告警。
- **G3 双模式**：`server`（服务器/容器）与 `ros2`（ROS2）两种守护模式，配置可切换，运行时生效。
- **G4 语义化**：把守护能力暴露为 LLM 工具，Bot 能「理解意图并执行」，如「睡觉」→ 夜间守护档位。
- **G5 安全**：所有破坏性动作受白名单、冷却、熔断、dry-run 约束，绝不允许 LLM 触发任意命令。
- **G6 可验收**：每一条需求都有对应的测试用例（C 系列）与验收判据。

### 1.3 非目标（本期边界）
- 不做 AstrBot 核心改造，不做平台适配器重写。
- 不做 WebUI 前端页面（本期以命令 + 通知 + 日志 + 状态文件承载；Pages 列为 Roadmap）。
- 不做跨主机集群编排（仅单机 Docker Compose）。
- 不做 ROS2 Service/Action 的业务级调用编排（仅健康探测与节点重启）。
- 不实现任意 shell 执行工具（安全红线）。

## 2. 术语表

| 术语 | 含义 |
| --- | --- |
| 探针 Probe | 一次可复用的健康检查单元，输入配置、输出 `ProbeResult` |
| 判定 Policy | 由 `ProbeResult` 与阈值规则推导出健康状态与建议动作的规则集 |
| 动作 Action | 对系统产生副作用的操作（重启容器、重登 QQ、切档位、发通知） |
| 事件 Incident | 一次「状态异常 + 采取动作 + 结果」的完整记录 |
| 档位 Profile | 运行强度预设：`normal` / `night` / `maintenance` / `aggressive` |
| 模式 Mode | 守护对象域：`server`（容器/QQ）或 `ros2`（节点/话题） |
| 目标 Target | 探针或动作作用的具名对象，如容器名 `astrbot`、节点名 `/camera_node` |
| 看门狗 Watchdog | 宿主机侧用于执行「自容器重启」的独立进程（systemd 单元） |
| 熔断 Circuit Breaker | 同一目标在窗口内动作次数超限后暂停自动动作并升级告警 |
| UMO | AstrBot 的 `unified_msg_origin`，会话唯一标识，用于主动推送 |

### 3.2 数据流（一次巡检）

```
Scheduler.tick()
  → HealthEngine.run_once(trigger="interval"|"command"|"llm"|"startup")
      → for probe in Mode.active_probes():  probe.check()  → ProbeResult
      → PolicyEngine.evaluate(results)     → [Finding(status, severity, suggested_action)]
      → for finding in findings:
            SafetyGuard.authorize(action, target, context)
              ├─ deny  → 记录 suppressed incident + 通知
              └─ allow → action.execute() → ActionResult
      → StateStore.record_incident(...)  +  AuditLog.append(...)
      → Notifier.dispatch(incidents)  (按 min_severity / rate_limit / dedup)
```

### 3.3 关键设计决策（ADR 摘要）

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | 用 Docker **HTTP API over unix socket** 而非 docker CLI | 容器内无需装 docker-cli；结构化 JSON 更可靠；避免 shell 注入面 |
| D2 | 保留 CLI fallback（可配置） | 某些受限环境 socket 不可用时降级 |
| D3 | 自重启默认走**看门狗** | 容器内自杀式重启会中断在途请求、日志丢失、易形成重启风暴 |
| D4 | 判定与动作分离（Policy / Action） | 便于单元测试：判定纯函数化，动作可 mock |
| D5 | 状态与审计落盘到 `data/` 而非插件目录 | 符合 AstrBot 插件规范，插件更新不丢数据 |
| D6 | LLM 工具参数**枚举化 + 白名单** | LLM 可能幻觉出任意容器名/命令，必须收口 |
| D7 | cron-lite 自研（无第三方依赖） | 降低依赖面；5 字段标准 cron 足够 |
| D8 | 一切副作用动作可 dry-run | 首次部署零风险试跑 |
| D9 | 巡检全程 `asyncio`，阻塞操作走 `to_thread`/子进程 | 不阻塞 AstrBot 事件循环 |
| D10 | 所有网络请求超时 + 重试上限 | 防止探针本身拖垮 Bot |

## 4. 模式（Mode）定义

| 模式 | 值 | 守护对象 | 默认探针集 |
| --- | --- | --- | --- |
| 服务器模式 | `server` | Docker 容器 + QQ 协议端 + 资源 | `docker_daemon` `container_health` `container_memory` `qq_login` `self_health` |
| ROS2 模式 | `ros2` | ROS2 节点/话题 + （可选）容器 | `ros2_nodes` `ros2_topics` `ros2_doctor` `docker_daemon`(可选) |

**模式语义**
- 模式只决定「启用哪些探针/动作」，**不影响**已注册的 LLM 工具集合（工具内部按当前模式裁剪可用目标）。
- 切换模式必须：停旧模式定时任务 → 等待在途巡检结束（带超时）→ 加载新模式探针 → 重置冷却窗口 → 落盘 → 通知。
- 服务器模式默认面向 **Arch Linux + Docker**，配置文件提供 `os_hint: arch` 与 `package_manager: pacman` 供诊断信息使用。

## 5. 档位（Profile）定义

| 档位 | 巡检间隔 | 告警阈值 | 自动动作 | 典型触发 |
| --- | --- | --- | --- | --- |
| `normal` | 60s | 标准 | 开启（受安全约束） | 默认 |
| `night`（夜间/睡觉） | 180s（更省资源） | 仅 `WARN` 以上通知 | 泄漏/掉线自动处理，**静默 INFO** | 用户说「睡觉/晚安/我休息了」 |
| `maintenance`（维护） | 暂停 | 静默全部 | 全部暂停 | 人工发版/调试 |
| `aggressive`（激进） | 20s | 更敏感 | 更积极自愈 | 故障排查期 |

**"睡觉"语义闭环（v0.2 修订）**：**不再依赖对话关键词**。改由「生命周期等级」自主推进：插件读取容器运行时长 → 按前端配置的等级阈值（I 级 = 运行 xx 小时，II 级 = xx 小时…）逐级升级 → **每个等级向 Bot 注入不同的提示词**（通过 `on_llm_request` 的 `extra_user_content_parts`）→ 促使 Bot 自行产生"该休息了"的意图并调用 `guardian_request_sleep` → 插件执行真正的睡眠（重启目标容器）。若在 `lifecycle.max_uptime_hours`（默认 720h = 30 天）内始终未发生睡眠，则由插件**强制睡眠**，保证 30 天内必定真睡至少一次。其余时间正常运行。

> **铁律（P1 自主触发原则）**：本插件**绝不**匹配对话中的任何关键词来触发动作。所有动作只由三类来源驱动：① 调度器周期巡检；② 生命周期等级推进；③ Bot（LLM）主动调用工具。用户消息文本仅用于 LLM 自主判断，插件层不做关键词匹配。

### 5.1 生命周期等级（Uptime Level）与自主睡眠

| 概念 | 说明 |
| --- | --- |
| 运行时长 | 由 Docker inspect 的 `State.StartedAt` 推导，单位小时；同时监控 astrbot 与 napcat 两个容器，取**最小值**作为"系统连续运行时长" |
| 等级 Level | 由运行时长落入的阈值区间决定，等级定义**完全由前端配置**（`lifecycle.levels`），默认 L0–L4 |
| 等级提示词 | 每个等级绑定一段 `prompt`，由插件注入到 Bot 的 LLM 上下文，等级越高语气越强、越明确引导"休息/睡眠" |
| 等级动作 | 每个等级可绑定 `action`：`none` / `notify` / `arm_sleep`（武装睡眠：等待 Bot 自主发起）/ `force_sleep`（强制睡眠） |
| 真睡眠 | 一次实际的重启动作（目标容器停机再启动），会中断服务若干秒——这才算"真睡觉" |
| 30 天保证 | `max_uptime_hours` 为硬上限（默认 720）；到达即 `force_sleep`，与 LLM 是否配合无关 |
| 睡眠后 | 记录 `last_sleep_at`，等级归零（因为容器已重启，运行时长归零），回到 `normal` 档位 |

默认等级表（可被前端完全覆盖）：

| 等级 | 触发条件（运行时长） | 注入提示词要点 | 动作 |
| --- | --- | --- | --- |
| L0 常规 | 0 – 168h | 无（不注入） | none |
| L1 I 级·轻提醒 | ≥ 168h（7 天） | 温和提及"已经连续工作很久了" | notify |
| L2 II 级·建议休息 | ≥ 360h（15 天） | 建议在合适时机安排一次休息 | notify |
| L3 III 级·准备睡眠 | ≥ 600h（25 天） | 明确表达"想睡一觉"，引导调用睡眠工具 | arm_sleep |
| L4 IV 级·强制睡眠 | ≥ 720h（30 天） | 宣布"必须睡了" | force_sleep |

## 6. 数据模型（models.py 契约）

```python
class Mode(str, Enum):      SERVER = "server";  ROS2 = "ros2"
class Profile(str, Enum):   NORMAL="normal"; NIGHT="night"; MAINTENANCE="maintenance"; AGGRESSIVE="aggressive"
class Status(str, Enum):    OK="ok"; WARN="warn"; CRIT="crit"; UNKNOWN="unknown"
class Severity(str, Enum):  INFO="info"; WARN="warn"; CRIT="crit"; FATAL="fatal"

@dataclass ProbeResult:
    probe: str                 # 探针名
    target: str                # 目标名（容器名/节点名/…）
    status: Status
    severity: Severity
    message: str               # 人类可读结论
    metrics: dict[str, Any]    # 结构化指标（mem_mb, restart_count, online, hz…）
    ts: float                  # epoch 秒
    raw: dict | None = None    # 原始响应（截断保存）

@dataclass Finding:
    probe: str; target: str; status: Status; severity: Severity
    reason: str
    suggested_action: ActionSpec | None

@dataclass ActionSpec:
    kind: str                  # restart_container | start_container | qq_relogin | ros2_restart | set_profile | notify
    target: str
    params: dict[str, Any] = field(default_factory=dict)
    dry_run: bool = False

@dataclass ActionResult:
    ok: bool; detail: str; elapsed_ms: int; output: str = ""

@dataclass Incident:
    id: str; ts: float; probe: str; target: str
    status: Status; severity: Severity; message: str
    action: ActionSpec | None; result: ActionResult | None
    suppressed: bool = False; suppress_reason: str = ""
    notified: bool = False
```

## 8. LLM 工具契约（LLM 可见）

| 工具名 | 参数 | 副作用 | 权限 |
| --- | --- | --- | --- |
| `guardian_health_report` | `scope`(all\|containers\|qq\|ros2) | 无（只读） | 所有用户 |
| `guardian_lifecycle_status` | 无 | 无（只读）：返回运行时长、当前等级、距下一等级/硬上限的剩余时间 | 所有用户 |
| `guardian_run_check` | `scope` | 可能触发自动动作 | 所有用户（动作仍受安全约束） |
| `guardian_diagnose` | `target`(枚举) | 无（只读） | 所有用户 |
| `guardian_list_incidents` | `limit`(1-50) | 无 | 所有用户 |
| `guardian_request_sleep` | `reason`(string), `duration_min`(number, 0-120) | **真睡眠（重启目标容器）** | 所有用户（受安全约束 + dry-run + 看门狗策略） |
| `guardian_restart_container` | `container`(枚举=白名单) | **重启容器** | 管理员 + 确认 |
| `guardian_set_mode` | `mode`(server\|ros2) | 切模式 | 管理员 |
| `guardian_set_profile` | `profile`(枚举) | 切档位 | 管理员 |

**关键约束**：`container` 与 `target` 参数在 docstring 中枚举化，运行时再次校验白名单；非白名单一律拒绝并回执说明。

**自主触发**：`guardian_request_sleep` 由 **Bot 自行决定**调用（受等级提示词引导），插件侧不解析任何对话关键词。等级到达 `force_sleep` 时，即使 Bot 未调用该工具，插件也会强制执行。

## 10. 安全红线（不可协商）

1. **禁止任意 shell**：LLM 永远不能传入自由文本命令；恢复命令只能来自配置白名单映射。
2. **白名单强制**：任何 `restart_container` / `start_container` 目标必须 ∈（`managed` ∪ `allowed_containers`）。
3. **受保护容器**：`astrbot` 本体默认受保护，需 `allow_self_restart=true` 且走看门狗/API 策略。
4. **冷却 + 熔断**：同目标动作间隔 < `action_cooldown_sec` 直接抑制；窗口内动作数 > `max_actions_per_hour` 触发熔断并升级 FATAL 告警。
5. **dry-run 默认开**：`dry_run=true` 时所有动作仅记录不执行。
6. **失败即停**：连续动作失败 N 次（默认 3）自动降级为只告警，并进入 `maintenance` 档位等待人工。
7. **审计不可关**：所有动作（含被抑制的）必须写审计日志。
8. **参数校验**：所有外部输入（LLM/命令）经 `safety` 层校验后才进入 action 层。

## 15. 风险登记册

| ID | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| R1 | 容器内自杀式重启形成风暴 | 服务雪崩 | 默认看门狗；冷却+熔断；失败即停 |
| R2 | docker.sock 权限不足 | 守护失效 | 文档化 `group_add`；启动自检并降级告警 |
| R3 | NapCat 重登需人工扫码 | 重登失败 | 优先「带会话重启」；失败升级 FATAL 通知 |
| R4 | LLM 幻觉调用破坏性工具 | 误重启 | 枚举参数 + 白名单 + 管理员 + 二次确认 |
| R5 | 探针阻塞事件循环 | Bot 卡顿 | 全程 async + 超时 + `to_thread` |
| R6 | 状态文件损坏 | 状态丢失 | 原子写（临时文件+rename）+ 备份 |
| R7 | 时区/时钟漂移导致 cron 误触发 | 非预期重启 | 记录并展示容器时区；cron 以本地时区解释 |
| R8 | 通知风暴 | 刷屏 | 限流 + 去重 + 档位静默 |
| R9 | ROS2 命令注入 | 任意执行 | 恢复命令仅来自配置白名单 |
| R10 | 插件热重载时旧定时器残留 | 重复巡检 | `terminate()` 严格取消任务 + 幂等启动 |
