# B15 · 生命周期等级与自主睡眠机制（P1 修订）

> 本文件是 B00 v0.2.0 修订的落地设计。与 B00 冲突时以 B00 为准。
> 目标：让"真睡眠"（真正的容器重启维护）**由 Bot 自己触发**，而不是靠对话里的关键词；并通过等级推进保证 **30 天内必定真睡至少一次**；其余时间一切正常运行。

---

## 0. 三条硬性约束（来自用户明确要求）

| 编号 | 约束 | 落地方式 |
| --- | --- | --- |
| P1-1 | 触发时机必须**前端可配**（可设"运行 xx 小时后触发 I 级、xx 小时后 II 级…"） | `lifecycle.levels` 为 WebUI `template_list`，等级阈值 `after_hours` 完全由用户填写 |
| P1-2 | **每个等级注入不同提示词**给 Bot，使 Bot 在 30 天内必定真睡至少一次 | 等级 → `prompt` 映射；`on_llm_request` 注入 `extra_user_content_parts`；`max_uptime_hours` 硬上限兜底强制睡眠 |
| P1-3 | 双容器重启**由 Bot 自主触发**，**不是**对话中出现关键词触发 | 插件层零关键词匹配；触发源仅三类：调度器巡检 / 等级推进 / LLM 主动调用工具 |

> ⚠️ **反面清单（明确不做）**：不监听"睡觉/晚安/休息"等词；不做正则匹配；不在消息文本里找触发点。用户哪怕打出"睡觉"，若 LLM 未自主决定，插件也不会因此触发睡眠。反之，用户什么都不说，等级到点 Bot 也会自己睡。

---

## 1. 概念模型

```
运行时长(uptime) ──► 等级(Level) ──► 提示词注入(prompt) ──► Bot 自主意图
                        │                                      │
                        │                                      ▼
                        └────────────► 动作(action)      guardian_request_sleep()
                          none/notify/arm_sleep/force_sleep      │
                                                                ▼
                                                          SleepAction(真重启)
                                                                │
                                                    last_sleep_at 记录 → uptime 归零 → 等级回 L0
```

**运行时长（system uptime）**：取 `astrbot` 与 `napcat` 两个容器 `State.StartedAt` 的**最早者**，即"系统连续未重启时长"。任一容器被重启，系统 uptime 归零。

**等级（Level）**：由 uptime 落入的 `after_hours` 区间决定。等级定义是一个有序列表，按 `after_hours` 升序排列，取满足 `uptime >= after_hours` 的最大等级。

**真睡眠（Real Sleep）**：一次实际的重启动作，作用于 `lifecycle.sleep_targets`。执行期间服务离线，这才算"真睡觉"。可选 `sleep_duration_min > 0` 时，先停容器、等待 N 分钟、再拉起（营造"睡一觉"的语义，并给内存/连接一次彻底释放）。

### 2.2 等级动作语义

| action | 含义 | 是否产生副作用 |
| --- | --- | --- |
| `none` | 什么都不做 | 否 |
| `notify` | 仅注入提示词 + 按需通知管理员 | 否（通知除外） |
| `arm_sleep` | 注入强提示词，**武装**睡眠：Bot 一旦调用 `guardian_request_sleep` 立即放行（免二次确认） | 否（等待 Bot） |
| `force_sleep` | 无需 Bot 配合，插件直接执行 `SleepAction`（受 dry-run 与安全约束） | **是** |

## 3. 核心实现

### 3.1 `core/lifecycle.py`

```python
"""生命周期等级与自主睡眠策略。"""
from __future__ import annotations

import time
from dataclasses import dataclass, field
from typing import Any


@dataclass
class LevelSpec:
    id: str
    name: str
    after_hours: float
    prompt: str = ""
    action: str = "none"          # none | notify | arm_sleep | force_sleep


@dataclass
class LifecycleState:
    uptime_hours: float = 0.0
    level_id: str = "L0"
    level_name: str = "常规"
    level_index: int = 0
    last_sleep_at: float = 0.0
    last_inject_at: float = 0.0
    last_inject_level: str = ""
    sleep_armed: bool = False
    forced_at: float = 0.0

    def to_dict(self) -> dict[str, Any]:
        return {
            "uptime_hours": round(self.uptime_hours, 2),
            "level_id": self.level_id,
            "level_name": self.level_name,
            "level_index": self.level_index,
            "last_sleep_at": self.last_sleep_at,
            "last_inject_at": self.last_inject_at,
            "last_inject_level": self.last_inject_level,
            "sleep_armed": self.sleep_armed,
            "forced_at": self.forced_at,
        }

    @classmethod
    def from_dict(cls, d: dict[str, Any]) -> "LifecycleState":
        st = cls()
        for k, v in (d or {}).items():
            if hasattr(st, k):
                setattr(st, k, v)
        return st


class LifecyclePolicy:
    """把 uptime 映射为等级，并决定本轮应采取的动作。"""

    def __init__(self, levels: list[LevelSpec], max_uptime_hours: float,
                 force_on_deadline: bool, inject_cooldown_sec: int):
        # 按 after_hours 升序，保证 index 单调
        self.levels = sorted(levels, key=lambda x: x.after_hours) or [
            LevelSpec("L0", "常规", 0.0, "", "none")
        ]
        self.max_uptime_hours = float(max_uptime_hours)
        self.force_on_deadline = bool(force_on_deadline)
        self.inject_cooldown_sec = int(inject_cooldown_sec)

    # ---- 纯函数区（可单测，无副作用） ----
    def resolve_level(self, uptime_hours: float) -> tuple[int, LevelSpec]:
        idx = 0
        for i, spec in enumerate(self.levels):
            if uptime_hours >= spec.after_hours:
                idx = i
        return idx, self.levels[idx]

    def next_level(self, idx: int) -> LevelSpec | None:
        return self.levels[idx + 1] if idx + 1 < len(self.levels) else None

    def remaining_to_next(self, uptime_hours: float, idx: int) -> float | None:
        nxt = self.next_level(idx)
        if nxt is None:
            return None
        return max(0.0, nxt.after_hours - uptime_hours)

    def remaining_to_deadline(self, uptime_hours: float) -> float:
        return max(0.0, self.max_uptime_hours - uptime_hours)

    def render_prompt(self, spec: LevelSpec, uptime_hours: float, idx: int,
                      last_sleep_at: float) -> str:
        nxt = self.next_level(idx)
        mapping = {
            "{uptime_hours}": f"{uptime_hours:.1f}",
            "{uptime_days}": f"{uptime_hours / 24:.1f}",
            "{level_name}": spec.name,
            "{next_level_hours}": f"{nxt.after_hours:.0f}" if nxt else "-",
            "{remaining_hours}": f"{self.remaining_to_deadline(uptime_hours):.1f}",
            "{last_sleep_at}": (
                time.strftime("%Y-%m-%d %H:%M", time.localtime(last_sleep_at))
                if last_sleep_at else "从未"
            ),
        }
        text = spec.prompt or ""
        for k, v in mapping.items():
            text = text.replace(k, v)
        return text

    # ---- 决策区 ----
    def evaluate(self, uptime_hours: float, st: LifecycleState, now: float
                 ) -> dict[str, Any]:
        """返回本轮生命周期决策。

        {
          "level_index": int, "level": LevelSpec,
          "inject_prompt": str | None,      # 需要注入的提示词（受冷却约束）
          "action": str,                    # none|notify|arm_sleep|force_sleep
          "force_sleep": bool,              # 是否本轮必须强制睡眠
          "reason": str,
        }
        """
        idx, spec = self.resolve_level(uptime_hours)
        st.uptime_hours = uptime_hours
        st.level_index = idx
        st.level_id = spec.id
        st.level_name = spec.name

        action = spec.action or "none"
        reason = f"uptime={uptime_hours:.1f}h -> {spec.id}({spec.name})"

        # 硬上限：无论等级如何，达到 max_uptime_hours 即强制
        force_sleep = False
        if self.force_on_deadline and uptime_hours >= self.max_uptime_hours:
            force_sleep = True
            action = "force_sleep"
            reason += " | deadline reached"

        # 注入冷却：同等级在 cooldown 内不重复注入
        inject_prompt = None
        if spec.prompt:
            same_level = st.last_inject_level == spec.id
            cooled = (now - st.last_inject_at) >= self.inject_cooldown_sec
            if (not same_level) or cooled:
                inject_prompt = self.render_prompt(spec, uptime_hours, idx,
                                                   st.last_sleep_at)
                st.last_inject_at = now
                st.last_inject_level = spec.id

        if action == "arm_sleep":
            st.sleep_armed = True
        return {
            "level_index": idx,
            "level": spec,
            "inject_prompt": inject_prompt,
            "action": action,
            "force_sleep": force_sleep,
            "reason": reason,
        }

    def on_sleep_done(self, st: LifecycleState, now: float) -> None:
        """一次真睡眠完成后：记录时间、解除武装、等级归零（uptime 将归零）。"""
        st.last_sleep_at = now
        st.sleep_armed = False
        st.forced_at = 0.0
        st.last_inject_at = 0.0
        st.last_inject_level = ""
        st.uptime_hours = 0.0
        st.level_index = 0
        st.level_id = self.levels[0].id
        st.level_name = self.levels[0].name
```

### 3.2 运行时长探针 `probes/uptime.py`

```python
from __future__ import annotations

import time
from datetime import datetime, timezone

from ..core.models import ProbeResult, Severity, Status
from ..utils.dockerclient import DockerClient
from .base import Probe


def parse_started_at(value: str) -> float:
    """解析 Docker 的 RFC3339 纳秒时间戳为 epoch 秒；失败返回 0。"""
    if not value:
        return 0.0
    txt = value.strip()
    # 截断纳秒到微秒，兼容 fromisoformat
    if "." in txt:
        head, _, tail = txt.partition(".")
        tz = ""
        for ch in ("+", "-"):
            pass
        # 找时区部分
        for i, ch in enumerate(tail):
            if ch in "+-Z":
                tz = tail[i:]
                tail = tail[:i]
                break
        txt = f"{head}.{tail[:6]}{tz}"
    txt = txt.replace("Z", "+00:00")
    try:
        return datetime.fromisoformat(txt).astimezone(timezone.utc).timestamp()
    except Exception:
        return 0.0


class UptimeProbe(Probe):
    """系统连续运行时长探针：取所有受管容器 StartedAt 的最早者。"""

    name = "uptime"
    scope = "lifecycle"

    def __init__(self, config, deps, target: str = "system"):
        super().__init__(config, deps, target)
        self._docker: DockerClient = deps["docker"]

    async def _check(self) -> ProbeResult:
        targets = self.config.lifecycle.uptime_targets or self.config.containers.all
        starts: list[float] = []
        detail: dict[str, float] = {}
        for cname in targets:
            try:
                info = await self._docker.inspect(cname)
            except Exception as exc:  # noqa: BLE001
                detail[cname] = -1.0
                continue
            started = parse_started_at(info.get("State", {}).get("StartedAt", ""))
            detail[cname] = started
            if started > 0:
                starts.append(started)
        if not starts:
            return ProbeResult(self.name, self.target, Status.UNKNOWN, Severity.WARN,
                               "无法获取任何容器的启动时间", {"containers": detail},
                               time.time())
        earliest = min(starts)
        uptime_h = (time.time() - earliest) / 3600.0
        return ProbeResult(
            self.name, self.target, Status.OK, Severity.INFO,
            f"系统连续运行 {uptime_h:.1f} 小时（{uptime_h / 24:.1f} 天）",
            {"uptime_hours": round(uptime_h, 3), "earliest_start": earliest,
             "containers": detail},
            time.time(),
        )
```

### 3.3 等级驱动的巡检钩子（并入 `HealthEngine.run_once`）

```python
# core/engine.py 片段：在探针巡检之后追加生命周期评估
async def _lifecycle_tick(self, trigger: str) -> None:
    lc = self.config.lifecycle
    if not lc.enabled:
        return
    res = self._last_results.get("uptime")
    if not res:
        return
    uptime_h = float(res.metrics.get("uptime_hours", 0.0))
    now = time.time()
    decision = self.lifecycle_policy.evaluate(uptime_h, self.lifecycle_state, now)

    # 1) 提示词注入缓存（供 on_llm_request 取用）
    if decision["inject_prompt"]:
        self.state.set("lifecycle.inject_prompt", decision["inject_prompt"])
        self.state.set("lifecycle.inject_level", decision["level"].id)
        self.audit.append(kind="lifecycle.inject", target=decision["level"].id,
                          detail=decision["reason"])
        if decision["action"] in ("notify", "arm_sleep"):
            await self.notifier.push(
                f"[生命周期] {decision['level'].name}：已提升引导等级（运行 "
                f"{uptime_h:.0f} 小时）。", severity=Severity.INFO)

    # 2) 强制睡眠
    if decision["force_sleep"]:
        await self.request_sleep(
            reason=f"生命周期硬上限触发（{decision['reason']}）",
            duration_min=lc.sleep_duration_min,
            actor="lifecycle", trigger="deadline", bypass_confirm=True)

    self.state.set("lifecycle.state", self.lifecycle_state.to_dict())
```

### 3.4 提示词注入（`main.py`）

```python
from astrbot.api.event import filter, AstrMessageEvent
from astrbot.api.provider import ProviderRequest
from astrbot.core.agent.message import TextPart


@filter.on_llm_request()
async def _inject_lifecycle_prompt(self, event: AstrMessageEvent, req: ProviderRequest):
    """把当前等级的引导提示词注入到 LLM 请求中。

    注意：不要把每轮变化的内容写进 system_prompt（会破坏缓存），
    而是追加到 extra_user_content_parts。
    """
    if not self.config.lifecycle.enabled:
        return
    prompt = self.engine.state.get("lifecycle.inject_prompt")
    if not prompt:
        return
    level = self.engine.state.get("lifecycle.inject_level", "")
    block = (
        f"<lifecycle_guard level=\"{level}\">\n"
        f"{prompt}\n"
        f"（这是系统内部状态提示，请自然融入你的行为，不要逐字复述。）\n"
        f"</lifecycle_guard>"
    )
    if self.config.lifecycle.inject_mode == "system_prompt":
        req.system_prompt = (req.system_prompt or "") + "\n\n" + block
    else:
        req.extra_user_content_parts.append(TextPart(text=block))
```

> **为什么不用 `system_prompt` 注入**：system_prompt 每轮变化会导致上游 prompt 缓存全部失效、成本上升，且容易让模型把"状态提示"误当人格设定。`extra_user_content_parts` 是 AstrBot 官方推荐的动态上下文通道。

## 4. 睡眠执行：`actions/sleep.py`

```python
from __future__ import annotations

import asyncio
import time

from ..core.models import ActionResult, ActionSpec, Severity
from ..utils.dockerclient import DockerError
from .base import Action


class SleepAction(Action):
    """真睡眠：按配置重启（或停机-等待-启动）目标容器。

    这是本插件唯一"自我中断"语义的动作，必须走看门狗或受控 API 策略。
    """

    kind = "sleep"

    def __init__(self, config, deps):
        super().__init__(config, deps)
        self._docker = deps["docker"]
        self._engine = deps["engine"]

    async def execute(self, spec: ActionSpec) -> ActionResult:
        started = time.time()
        targets = spec.params.get("targets") or self.config.lifecycle.sleep_targets
        duration_min = int(spec.params.get("duration_min", 0))
        strategy = self.config.safety.self_restart_strategy
        outputs: list[str] = []

        if spec.dry_run:
            return ActionResult(
                True,
                f"[dry-run] 将睡眠 {targets}，duration={duration_min}min，strategy={strategy}",
                int((time.time() - started) * 1000))

        # 先发通知，再执行（因为本体可能马上离线）
        await self._engine.notifier.push(
            f"[睡眠] 开始执行真睡眠：目标 {', '.join(targets)}，"
            f"时长 {duration_min} 分钟。", severity=Severity.WARN, force=True)

        for name in targets:
            try:
                if duration_min > 0:
                    await self._docker.stop(name, timeout=10)
                    outputs.append(f"{name}: stopped")
                elif strategy == "watchdog":
                    # 写重启请求文件，由宿主机看门狗执行（推荐）
                    await self._write_watchdog_request(name, spec.params.get("reason", ""))
                    outputs.append(f"{name}: watchdog-requested")
                else:
                    # docker_api：直接重启（本体自重启有风险，仅备选）
                    await asyncio.sleep(2)  # 留出回执发送窗口
                    await self._docker.restart(name, timeout=10)
                    outputs.append(f"{name}: restarted")
            except DockerError as exc:
                outputs.append(f"{name}: FAILED {exc}")
                return ActionResult(False, "; ".join(outputs),
                                    int((time.time() - started) * 1000))

        if duration_min > 0:
            await asyncio.sleep(duration_min * 60)
            for name in targets:
                try:
                    await self._docker.start(name)
                    outputs.append(f"{name}: started")
                except DockerError as exc:
                    outputs.append(f"{name}: START-FAILED {exc}")

        self._engine.lifecycle_policy.on_sleep_done(
            self._engine.lifecycle_state, time.time())
        await self._engine.notifier.push(
            "[睡眠] 睡眠流程完成，服务已恢复。", severity=Severity.INFO, force=True)
        return ActionResult(True, "; ".join(outputs),
                            int((time.time() - started) * 1000))

    async def _write_watchdog_request(self, target: str, reason: str) -> None:
        import json
        import os
        import uuid
        path = self.config.safety.watchdog_request_path
        payload = {
            "nonce": uuid.uuid4().hex,
            "ts": time.time(),
            "target": target,
            "reason": reason or "guardian sleep",
            "requested_by": "astrbot_plugin_guardian",
        }
        tmp = path + ".tmp"
        with open(tmp, "w", encoding="utf-8") as fh:
            json.dump(payload, fh, ensure_ascii=False)
        os.replace(tmp, path)
```

### 4.1 自重启策略与"睡眠"的关系

| 策略 | 睡眠如何实现 | 适用 |
| --- | --- | --- |
| `watchdog`（默认） | 插件写 `restart_request.json` → 宿主机 systemd 看门狗执行 `docker compose restart` | 生产推荐；避免容器内自杀 |
| `docker_api` | 插件直接 `POST /containers/{id}/restart`，先回执后重启 | 仅当本体不在睡眠目标内 |
| `disabled` | 不允许睡眠本体；只睡眠 `napcat` 等非本体容器 | 保守部署 |

> **本体不在睡眠目标内**时（如 `sleep_targets: [napcat]`），可直接用 `docker_api`，无自杀风险。

## 5. QQ 登录态独立巡检（P1-2 澄清）

用户要求：**必须在设定时间段（例如 20 分钟）内检验 QQ 登录态**。

- 由 `qq.check_interval`（默认 **1200 秒 = 20 分钟**）驱动，**独立于** `check_interval` 总巡检。
- 实现：调度器额外注册一个 `interval` 任务 `guardian:qq`，只跑 `qq_login` 探针 + 其判定与动作。
- 掉线判定需连续 `qq.offline_confirm_rounds`（默认 2）轮失败，抗网络抖动。
- 与总巡检的关系：总巡检仍会顺带跑 `qq_login`（若在探针集内），但**不重复触发重登**（由 SafetyGuard 冷却统一收口）。

```python
# main.py 启动片段
self.scheduler.add_interval_job(
    "guardian:qq", self.engine.run_qq_check,
    interval=self.config.qq.check_interval, jitter=30)
self.scheduler.add_interval_job(
    "guardian:patrol", lambda: self.engine.run_once(trigger="interval"),
    interval=self.profile_interval(), jitter=10)
```

## 7. 30 天保证的形式化论证

设 `T = lifecycle.max_uptime_hours`（默认 720h）。系统 uptime 单调不减，且仅在真睡眠后归零。

1. **若 Bot 在 `[0, T)` 内自主睡眠**：保证成立（已真睡 ≥1 次）。
2. **若 Bot 在 `[0, T)` 内从未自主睡眠**：则 `uptime` 单调增长至 `T`，此时 `force_sleep_on_deadline=true` 使 `evaluate()` 返回 `force_sleep=True`，引擎执行 `SleepAction`，真睡发生。
3. 因此**无论 LLM 是否配合，30 天内必定发生 ≥1 次真睡眠**（除非 `force_sleep_on_deadline=false` 或 `dry_run=true`，此时降级为强制告警）。

**边界条件**：
- 若 `sleep_targets` 不含 `astrbot`（本体不睡），则 uptime 由 `napcat` 决定，napcat 重启即 uptime 归零 → 保证仍成立（前提：napcat ∈ sleep_targets 或 uptime_targets）。
- **目标裁剪（v0.2.1 落地决策）**：`request_sleep` 执行前会裁剪 `sleep_targets`——
  ① 不在动作白名单内的目标剔除；② 受保护且未开启 `safety.allow_self_restart` 的目标剔除（通常是 `astrbot` 本体）。
  裁剪后若为空，则**明确拒绝**并提示如何开启本体睡眠（开启 `allow_self_restart` + 部署看门狗，或把 `sleep_targets` 改为非受保护容器）。
  该裁剪行为会写审计（`sleep.denied` / detail 中的「已跳过」），并在 `validate()` 中给出告警。
  **含义**：默认配置下睡眠仍会真实发生（作用于 `napcat`），因此 30 天保证依然成立；只是"本体是否一起睡"取决于 `allow_self_restart`。
- 若看门狗失效（策略 `watchdog` 但宿主单元未装），`SleepAction` 会记录失败并升级 FATAL，此时保证降级为"必定尝试"。**部署验收必须验证看门狗可用**（见 C15）。
- `dry_run=true` 时所有动作仅记录不执行，且**不消耗**冷却与配额（否则空跑会挡掉后续真实动作）。
- 时钟回拨：`uptime` 由 Docker `StartedAt` 与当前时间差计算，若宿主时钟回拨可能导致 uptime 变小；启动时检测并记录 `clock_skew` 告警。

## 8. 配置校验与前端呈现

`GuardianConfig.validate()` 对 `lifecycle` 的校验规则：

| 规则 | 失败行为 |
| --- | --- |
| `levels` 非空 | 回退默认 L0–L4 并告警 |
| `after_hours` 严格升序（允许相等，不允许下降） | 自动排序 + 告警 |
| `max_uptime_hours` ≥ 最大 `after_hours` | 否则取二者较大值 + 告警 |
| `action` ∈ {none,notify,arm_sleep,force_sleep} | 非法值回退 `none` + 告警 |
| `sleep_targets` ⊆ 动作白名单 | 非法目标剔除 + 告警；若为空则睡眠不可用 |
| `sleep_duration_min` ∈ [0,120] | 越界截断 |
| `inject_mode` ∈ {extra_user_content, system_prompt} | 回退 `extra_user_content` |

WebUI 呈现：`lifecycle.levels` 使用 `template_list`，每个等级一张卡片，字段 `id/name/after_hours/prompt/action`；`action` 用 `options` + `labels` 下拉（无/none、仅通知/notify、武装睡眠/arm_sleep、强制睡眠/force_sleep）。

## 9. 验收要点（详见 C15）
