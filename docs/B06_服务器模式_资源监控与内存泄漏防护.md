## 1. 目标与范围

| 编号 | 目标 | 判据 |
| --- | --- | --- |
| G1 | 采集容器内存/CPU 真实占用 | 使用 `docker stats` 并做 cache 修正，不虚高 |
| G2 | 提前发现泄漏趋势 | 滑动窗口线性回归，估算 MB/小时增长率 |
| G3 | 阈值告警 | `memory.warn_mb` / `crit_mb` / `growth_warn_mb_per_hour` 三级判定 |
| G4 | 可选自动重启 | 仅在 `memory.restart_on_leak=true` 时动作，且受 `memory.leak_cooldown` 约束 |
| G5 | 事后可取证 | OOM 或重启前保留样本快照，可复盘 |

范围内：`GET /containers/{id}/stats?stream=false` 采集、cache 修正、CPU 百分比、滑动窗口、增长率拟合、阈值与档位联动、OOM 取证、样本持久化。范围外：cgroup 直接读写、进程级内存剖析（`pmap`/`tracemalloc`）、宿主整机内存监控（仅做附加提示）。

## 2. 为什么 Docker 容器会「内存泄漏」

| 根因 | 机制 | 在本项目中的典型表现 |
| --- | --- | --- |
| Python 长期驻留 | 解释器不归还已分配 arena 给 OS，`free()` 后 RSS 不降 | astrbot 容器内存阶梯式上台阶后不回落 |
| 连接未释放 | `aiohttp.ClientSession` / socket / 文件句柄未 `close()` | 每次巡检泄漏若干 KB，长跑后显著 |
| 缓存无上限 | 消息缓存、LRU 缺失、`dict` 只增不删 | 与消息量正相关，重启后归零 |
| GC 不及时 | 循环引用 + `gc` 未触发、`__del__` 阻塞 | 周期性 GC 尖峰，均值缓慢抬升 |
| 事件监听器堆积 | 热重载后旧监听器未注销（B00 R10） | 每次 reload 抬升一档 |
| 原生扩展/子进程 | 第三方库 C 层泄漏 | `to_thread`/子进程退出后未回收 |

**关键区分**：`usage` 中包含 page cache，Linux 在内存压力下可回收，**不计入泄漏**。因此必须以 `usage - cache` 作为判据（Docker CLI 的 `MEM USAGE` 即采用此口径）。

## 3. 指标采集方案

```
Scheduler.tick()
  └─ ContainerMemoryProbe.check()
       1. GET /containers/{id}/stats?stream=false      （单次快照，非流式）
       2. used = memory_stats.usage - cache            （cgroup v1: stats.cache；v2: stats.inactive_file）
       3. limit = memory_stats.limit
       4. cpu% = (cpu_delta / system_delta) * online_cpus * 100
       5. 追加样本 {ts, mb, cpu} 到环形缓冲（上限 memory.samples，且仅保留 6h 内）
       6. 计算 current / peak / avg / slope(MB/h) / R²
       7. 判定 warn / crit / leak -> ProbeResult.metrics
```

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `mem_mb` | `(memory_stats.usage - cache) / 2^20` | 真实占用（PolicyEngine 阈值判据） |
| `limit_mb` | `memory_stats.limit / 2^20` | 容器内存上限（未限制时极大值） |
| `usage_pct` | `used_mb / limit_mb` | 距 OOM 的距离 |
| `cache_mb` | `stats.cache` 或 `stats.inactive_file` | 可回收页缓存，单独记录便于排障 |
| `cpu_pct` | 见上公式 | 附带监控（§10） |
| `peak_mb` / `avg_mb` | 窗口内样本 | 趋势背景 |
| `growth_mb_per_hour` | 线性回归 | 泄漏速率（PolicyEngine 阈值判据） |
| `r2` | 拟合优度 | 过滤噪声（`< R2_MIN` 视为噪声，不判泄漏） |

## 4. `probes/container_memory.py`（完整代码）

> 接口约定同 B04 §3：继承 `probes.base.Probe`、实现 `_check()`、`@register_probe("container_memory")` 注册；按 target 实例化（`ContainerMemoryProbe(config, deps, "napcat")`）。

```python
# src/astrbot_plugin_guardian/probes/container_memory.py
from __future__ import annotations
import json, os, time
from ..core.models import ProbeResult, Severity, Status
from ..core.registry import register_probe
from ..utils.dockerclient import DockerError, DockerUnavailable
from .base import Probe
SAMPLE_MAX_AGE_SEC = 6 * 3600        # 样本最长保留 6 小时
COLD_START_SEC = 900                 # 冷启动豁免期 15 分钟（启动期内存自然爬升）
MIN_SAMPLES_FOR_SLOPE = 5            # 拟合所需最少样本
MIN_SPAN_SEC = 1200                  # 拟合跨度下限 20 分钟
R2_MIN = 0.6                         # 拟合可信度下限，低于则视为噪声
PROFILE_SCALE = {"normal": 1.0, "night": 1.0, "aggressive": 0.85, "maintenance": 1.0}
@register_probe("container_memory")
class ContainerMemoryProbe(Probe):
    """容器内存探针：滑动窗口采样 + 线性回归估算泄漏速率，按档位缩放阈值。"""
    name = "container_memory"
    def __init__(self, config, deps, target: str) -> None:
        super().__init__(config, deps, target=target)
        self.docker, self.state, self.log = deps["docker"], deps["state"], deps.get("log")
    async def _check(self) -> ProbeResult:
        ts = time.time()
        try:
            stats = await self.docker.stats(self.target)
        except DockerError as exc:
            if exc.status == 404:
                return self._r(ts, Status.CRIT, Severity.CRIT, f"容器 {self.target} 不存在",
                               {"exists": False}, {"http_status": 404})
            return self._r(ts, Status.UNKNOWN, Severity.WARN, f"stats 失败：{exc.message[:120]}",
                           {"exists": None}, {"http_status": exc.status})
        except DockerUnavailable as exc:
            return self._r(ts, Status.UNKNOWN, Severity.WARN, "Docker 不可达，无法采样内存",
                           {"exists": None, "error": str(exc)[:160]}, None)
        used_mb, cache_mb, limit_mb = self._memory(stats)
        cpu_pct = self._cpu_pct(stats)
        await self._append_sample(ts, used_mb, cpu_pct)
        samples = await self._load_samples()
        peak_mb = round(max(s["mb"] for s in samples), 1) if samples else used_mb
        avg_mb = round(sum(s["mb"] for s in samples) / len(samples), 1) if samples else used_mb
        span = (samples[-1]["ts"] - samples[0]["ts"]) if len(samples) >= 2 else 0.0
        slope, r2 = self._slope_mb_per_hour(samples)
        uptime = await self._container_uptime()
        scale = PROFILE_SCALE.get(str(self.config.profile), 1.0)
        warn_mb = float(self.config.memory_warn_mb) * scale
        crit_mb = float(self.config.memory_crit_mb) * scale
        growth_warn = float(self.config.memory_growth_mb_per_hour) * scale
        allow_restart = bool(self.config.memory_restart_on_leak)
        metrics = {"exists": True, "mem_mb": used_mb, "cache_mb": cache_mb, "limit_mb": limit_mb,
                   "usage_pct": round(used_mb / limit_mb * 100, 2) if limit_mb > 0 else None,
                   "cpu_pct": cpu_pct, "peak_mb": peak_mb, "avg_mb": avg_mb,
                   "samples": len(samples), "span_sec": int(span),
                   "growth_mb_per_hour": slope, "r2": r2, "cold_start": uptime < COLD_START_SEC,
                   "thresholds": {"warn_mb": warn_mb, "crit_mb": crit_mb, "growth": growth_warn},
                   "suggested": "restart_container" if allow_restart else None}
        # 判定优先级：绝对阈值 > 泄漏趋势 > 正常
        if used_mb >= crit_mb:
            return self._r(ts, Status.CRIT, Severity.CRIT,
                           f"内存 {used_mb}MB 超严重阈值 {crit_mb}MB（距上限 {limit_mb}MB）", metrics, None)
        if used_mb >= warn_mb:
            return self._r(ts, Status.WARN, Severity.WARN,
                           f"内存 {used_mb}MB 超告警阈值 {warn_mb}MB", metrics, None)
        leak_ok = (not metrics["cold_start"] and len(samples) >= MIN_SAMPLES_FOR_SLOPE
                   and span >= MIN_SPAN_SEC and r2 >= R2_MIN)
        if leak_ok and slope >= growth_warn * 2:
            return self._r(ts, Status.CRIT, Severity.CRIT,
                           f"内存增长 {slope}MB/h（≥2× 阈值 {growth_warn}，R²={r2}），判定泄漏", metrics, None)
        if leak_ok and slope >= growth_warn:
            return self._r(ts, Status.WARN, Severity.WARN,
                           f"内存增长 {slope}MB/h 超阈值 {growth_warn}（R²={r2}），疑似泄漏", metrics, None)
        return self._r(ts, Status.OK, Severity.INFO,
                       f"内存 {used_mb}MB（峰值 {peak_mb}，增长 {slope}MB/h，R²={r2}）", metrics, None)
    # ---------- 指标计算 ----------
    @staticmethod
    def _memory(stats: dict) -> tuple[float, float, float]:
        mem = stats.get("memory_stats") or {}
        usage = int(mem.get("usage") or 0)
        st = mem.get("stats") or {}
        cache = int(st.get("cache") or st.get("inactive_file") or 0)   # v1: cache / v2: inactive_file
        limit = int(mem.get("limit") or 0)
        return (round(max(0, usage - cache) / 2**20, 1), round(cache / 2**20, 1), round(limit / 2**20, 1))
    @staticmethod
    def _cpu_pct(stats: dict) -> float | None:
        try:
            cpu, pre = stats["cpu_stats"], stats.get("precpu_stats") or {}
            delta = cpu["cpu_usage"]["total_usage"] - pre["cpu_usage"]["total_usage"]
            sysd = cpu["system_cpu_usage"] - pre["system_cpu_usage"]
            if delta <= 0 or sysd <= 0: return None
            ncpu = cpu.get("online_cpus") or len(cpu["cpu_usage"].get("percpu_usage") or [1])
            return round(delta / sysd * ncpu * 100, 2)
        except (KeyError, TypeError, ZeroDivisionError):
            return None
    @staticmethod
    def _slope_mb_per_hour(samples: list) -> tuple[float, float]:
        """最小二乘线性回归：slope = Σ(x-x̄)(y-ȳ) / Σ(x-x̄)²，x 为秒；返回 (MB/小时, R²)。"""
        pts = [(s["ts"], s["mb"]) for s in samples]
        n = len(pts)
        if n < 3: return 0.0, 0.0
        mx = sum(p[0] for p in pts) / n
        my = sum(p[1] for p in pts) / n
        sxx = sum((p[0] - mx) ** 2 for p in pts)
        sxy = sum((p[0] - mx) * (p[1] - my) for p in pts)
        syy = sum((p[1] - my) ** 2 for p in pts)
        if sxx <= 0: return 0.0, 0.0
        r2 = (sxy * sxy) / (sxx * syy) if syy > 0 else 0.0
        return round(sxy / sxx * 3600, 2), round(r2, 3)
    # ---------- 样本持久化（跨重启保留） ----------
    def _path(self) -> str:
        safe = "".join(c for c in self.target if c.isalnum() or c in "-_")
        return os.path.join(str(self.config.data_dir), f"memory_samples_{safe}.json")
    async def _load_samples(self) -> list:
        now = time.time()
        try:
            with open(self._path(), "r", encoding="utf-8") as fh:
                data = json.load(fh)
            samples = [s for s in data.get("samples", []) if now - float(s["ts"]) <= SAMPLE_MAX_AGE_SEC]
        except (OSError, ValueError, KeyError, TypeError):
            samples = []
        keep = max(int(self.config.memory_samples), MIN_SAMPLES_FOR_SLOPE) * 3
        return samples[-keep:]
    async def _append_sample(self, ts: float, mb: float, cpu: float | None) -> None:
        samples = await self._load_samples()
        samples.append({"ts": ts, "mb": mb, "cpu": cpu})
        payload = {"target": self.target, "updated": ts,
                   "started_at": await self._container_started_at(), "samples": samples[-200:]}
        tmp = f"{self._path()}.tmp"
        os.makedirs(str(self.config.data_dir), exist_ok=True)
        with open(tmp, "w", encoding="utf-8") as fh:
            json.dump(payload, fh, ensure_ascii=False)   # 原子写：临时文件 + os.replace
        os.replace(tmp, self._path())
    async def _container_started_at(self) -> str:
        try:
            return str(((await self.docker.inspect(self.target)).get("State") or {}).get("StartedAt") or "")
        except (DockerError, DockerUnavailable):
            return ""
    async def _container_uptime(self) -> int:
        try:
            s = (await self._container_started_at()).split(".")[0].replace("Z", "+00:00")
            from datetime import datetime, timezone
            return max(0, int(time.time() - datetime.fromisoformat(s).replace(tzinfo=timezone.utc).timestamp()))
        except Exception:
            return 10 ** 9        # 解析失败时不启用冷启动豁免，交由阈值判定
    def _r(self, ts, status, sev, msg, metrics, raw) -> ProbeResult:
        return ProbeResult(probe=self.name, target=self.target, status=status,
                           severity=sev, message=msg, metrics=metrics, ts=ts, raw=raw)
```

## 5. 泄漏判定算法详解

**斜率估计**：对窗口内样本 `(t_i, mb_i)` 做最小二乘：

```
slope = Σ(t_i - t̄)(m_i - m̄) / Σ(t_i - t̄)²     单位 MB/s
slope_mb_per_hour = slope × 3600
R²    = (Σ(t_i - t̄)(m_i - m̄))² / (Σ(t_i - t̄)² · Σ(m_i - m̄)²)
```

| 门槛 | 值 | 原因 |
| --- | --- | --- |
| 样本数 ≥ `MIN_SAMPLES_FOR_SLOPE` | 5 | 少于 5 点回归无统计意义 |
| 时间跨度 ≥ `MIN_SPAN_SEC` | 1200s | 短跨度内斜率噪声极大 |
| `R² ≥ R2_MIN` | 0.6 | 过滤"GC 锯齿"造成的伪趋势 |
| 冷启动豁免 | 容器运行 < 900s 跳过泄漏判定 | 启动期缓存/连接池填充属正常爬升 |
| 绝对阈值优先 | `used_mb ≥ warn/crit` 直接判定 | 阈值比趋势更确定，避免被斜率掩盖 |
| 双阈值泄漏 | `slope ≥ 2×growth` → CRIT；`≥ growth` → WARN | 分级响应 |

**噪声过滤要点**
1. cache 修正：页缓存随 I/O 波动，不修正会产生数十 MB 的假波动。
2. 采样点必须来自 `stream=false` 的瞬时快照，避免流式数据的窗口平均效应。
3. 重启边界：容器 `StartedAt` 变化后，新样本属于新实例；**跨重启样本不参与斜率计算**（仅保留用于取证与趋势展示），否则重启会造成负斜率假象。
4. 尖峰不删点：不剔除最大值，改用 R² 判定整体线性度。

## 6. 阈值与档位联动表

| 档位 | 系数 `PROFILE_SCALE` | warn_mb(默认 700) | crit_mb(默认 1100) | growth(默认 80MB/h) | 意图 |
| --- | --- | --- | --- | --- | --- |
| `normal` | ×1.00 | 700 | 1100 | 80 | 基准 |
| `night` | ×1.00 | 700 | 1100 | 80 | 夜间不放大灵敏度，避免误触发重启打扰休息 |
| `aggressive` | ×0.85 | 595 | 935 | 68 | 排查期更敏感 |
| `maintenance` | — | 探针不调度 | — | — | 全部暂停（B00 §5） |

> 判定优先级：`crit_mb` > `warn_mb` > 泄漏趋势。档位切换后**不清空样本**（样本是客观观测），仅改变阈值系数。

**对 `core/policy.py::DEFAULT_RULES` 的贡献（B03 §5 已含 `container_memory` 基线规则，此处补充）**

| 探针 | metric | op | threshold | status | severity | action_kind |
| --- | --- | --- | --- | --- | --- | --- |
| `container_memory` | `mem_mb` | `>=` | `memory.crit_mb`（默认 1100） | CRIT | CRIT | `restart_container`（仅 `restart_on_leak=true`，否则置空） |
| `container_memory` | `mem_mb` | `>=` | `memory.warn_mb`（默认 700） | WARN | WARN | — |
| `container_memory` | `growth_mb_per_hour` | `>=` | `memory.growth_warn_mb_per_hour`（默认 80） | WARN | WARN | — |
| `container_memory` | `r2` | `>=` | 0.6 | —（前置条件，由探针内部完成） | — | — |

> `r2`、`samples`、`span_sec`、`cold_start` 是**探针内部**的判定前提（探针已把不满足条件的样本判为 OK），不进入 PolicyEngine 规则，避免阈值表与统计前提耦合。档位缩放后的阈值写入 `metrics.thresholds`，`DEFAULT_RULES` 在档位切换时由 `main.py` 重建（B02/B10）。

## 7. actions 侧：泄漏触发的重启

泄漏不新增 Action 类型，直接复用 `RestartContainerAction`（B04 §7），但叠加独立冷却：

```
Finding(status=CRIT/WARN, suggested_action=ActionSpec(kind="restart_container", target=<容器>))
  └─ SafetyGuard.authorize()
       ├─ 白名单校验（managed ∪ allowed_containers）
       ├─ action_cooldown_sec（通用冷却）
       ├─ max_actions_per_hour（熔断）
       └─ memory.leak_cooldown（泄漏专用冷却，默认 3600s）★
  └─ RestartContainerAction.execute() -> 复核 running -> 记 action.last_restart.<name>
```

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `memory.restart_on_leak` | false | **是否允许泄漏触发重启**；false 时 `suggested=None`，仅告警 |
| `memory.leak_cooldown` | 3600 | 同一容器两次「泄漏触发重启」的最小间隔（与通用冷却取更严格者） |

实现约定：泄漏触发的重启需在 `ActionSpec.params` 中带 `{"reason": "memory_leak", "cooldown_key": "memory_leak"}`，SafetyGuard 据此选用 `memory.leak_cooldown` 而非 `action_cooldown_sec`。

## 8. 「重启即泄漏掩盖」的反思与替代策略

**问题**：重启能让内存立刻回落，但**根因未消除**——若不记录重启前状态，运维只看到"内存正常了"，泄漏被系统性掩盖，且重启频率会随时间升高，最终演变为重启风暴（B00 R1）。

| 策略 | 说明 | 默认 |
| --- | --- | --- |
| 优先告警 | `restart_on_leak=false`，只推 WARN/CRIT 与趋势数据，由人决策 | ✔ |
| 可选重启 | `restart_on_leak=true` 时才动作，且受 `leak_cooldown` 与熔断约束 | — |
| 重启前快照 | 动作前把当前样本窗口、峰值、斜率、R² 写入 `data/memory_snapshots_<c>.json` | ✔ |
| 日志诊断建议 | 通知中附带「建议同时开启容器日志诊断 / `tracemalloc` 采样」提示 | ✔ |
| 重启计数追踪 | 统计 7 天内泄漏重启次数；≥3 次时升级 FATAL 并提示需根治 | ✔ |
| 抑制重复重启 | 冷却期内即使仍超阈值也不重启，只告警 | ✔ |

**通知文案模板（含证据）**：
```
[CRIT] 容器 napcat 内存 1180MB（阈值 1100MB）
趋势：+142MB/h（R²=0.91，窗口 10 点 / 2.1h）  峰值 1185MB  均值 1050MB
快照已保存：data/memory_snapshots_napcat.json（时间 2026-10-13 04:12:03）
建议：优先排查连接/缓存是否释放；如需临时缓解可执行 /guardian restart napcat
```

## 9. OOMKilled 的事后取证

当 `container_health` 探针发现 `State.OOMKilled=true`（B04 §5）时，触发取证流程：

| 步骤 | 数据源 | 产出 |
| --- | --- | --- |
| 1 | `GET /containers/{id}/json` → `State.OOMKilled` / `State.ExitCode` / `State.FinishedAt` | 确认 OOM 与退出时刻 |
| 2 | `GET /events?filters={"container":[<id>],"event":["oom","die","kill"]}` | 事件时间线（`oom` 事件精确到容器） |
| 3 | `data/memory_samples_<c>.json` 最后一次采样 | 死亡前内存值、斜率、R² |
| 4 | `HostConfig.Memory` / `MemorySwap` | 是否存在硬上限（有上限才会 OOM） |
| 5 | 汇总写入 `data/oom_reports/<容器>_<ts>.json` + 审计 | 可复盘证据包 |

```
[FATAL] 容器 napcat 因 OOM 被杀
时间：2026-10-13 04:12:03   退出码：137
死亡前 30 分钟内存：905MB -> 1185MB（+560MB，斜率 +310MB/h，R²=0.94）
容器内存上限：1200MB（HostConfig.Memory）
结论：典型泄漏型 OOM。已保存证据包，建议排查连接/缓存释放。
```

**要点**：`ExitCode=137` 是 OOM/SIGKILL 的强信号，但**不能单独断言 OOM**，必须以 `State.OOMKilled=true` 或 `oom` 事件为准（137 也可能来自 `docker kill`）。

## 10. CPU 与磁盘的附加监控（可选）

| 指标 | 采集 | 阈值 | 处置 |
| --- | --- | --- | --- |
| 容器 CPU% | `cpu_stats`（同 §4 `_cpu_pct`） | 连续 3 次 ≥ 90% | WARN，通知（不自动重启，避免误伤） |
| 数据盘使用率 | `shutil.disk_usage(data_dir)`（B04 `self_health`） | ≥85% WARN / ≥95% CRIT | 告警 + 建议清理 `data/` 旧审计与快照 |
| 磁盘 I/O | `stats.blkio_stats` | 仅记录不告警 | 排障参考 |
| 网络 I/O | `stats.networks` | 仅记录不告警 | 排障参考 |

约定：CPU/磁盘**不触发自动动作**（B00 §10 未授予该权限），只作为上下文指标写入 `ProbeResult.metrics`。

## 11. 采样持久化（跨重启保留）

| 关注点 | 设计 |
| --- | --- |
| 存储位置 | `data/memory_samples_<container>.json`（B00 D5：数据目录而非插件目录） |
| 原子写 | 临时文件 + `os.replace`，避免损坏（B00 R6） |
| 保留策略 | 仅保留 6 小时内样本；文件内最多保留最近 200 点 |
| 跨重启保留 | **保留**：重启后样本继续累积，避免每次重启后 15 分钟冷启动豁免期导致的观测盲区 |
| 实例分段 | 文件内记录 `started_at`；`StartedAt` 变化即视为新实例，斜率仅用**当前实例**样本计算 |
| 跨重启用途 | 旧实例样本用于趋势对比与取证（"上次重启前是多少"），不参与泄漏判定 |
| 损坏容错 | 解析失败视为空窗口，重新开始采样，不影响巡检 |

## 12. 性能开销评估

| 项 | 量级 | 说明 |
| --- | --- | --- |
| `stats?stream=false` 单次 | 约 10~60 ms，返回数十 KB | 服务端做一次 cgroup 读取，对容器扰动可忽略 |
| 采样频率 | 每 `check_interval` 一次（normal 60s / night 180s / aggressive 20s） | 即 1/60 ~ 3 次/分钟 |
| 磁盘写 | 每样本重写一次 JSON（≤200 点，约 20 KB） | 6h 内约 360 次写；可接受，必要时可降为每 N 次落盘 |
| CPU 开销 | 回归为 O(n)，n ≤ 200 | 微秒级 |
| 事件循环阻塞 | 全部 `await`，无阻塞调用 | 符合 B00 D9 |
| 对被测容器的扰动 | 无（只读 cgroup 统计，不发信号） | 无侵入 |

**调优建议**：`aggressive` 档位下把采样频率提到 20s，样本窗口相应缩短；`night` 档位下 180s 采样仍满足 `MIN_SPAN_SEC=1200s`（7 点）。

## 13. 验收标准（对应 C06）

- [ ] C06-01 `metrics.mem_mb` 等于 `(memory_stats.usage - cache) / 2^20`，与 `docker stats` 的 `MEM USAGE` 偏差 < 1MB。
- [ ] C06-02 样本数 < 5 或跨度 < 1200s 时不产生泄漏判定（仅记录斜率）。
- [ ] C06-03 人为注入线性增长（如循环分配）后，`metrics.growth_mb_per_hour` 与实际增长率偏差 < 20%，`r2 ≥ 0.9`。
- [ ] C06-04 锯齿型波动（分配后释放）场景 `r2 < 0.6`，不判泄漏。
- [ ] C06-05 内存超过 `warn_mb` 产生 WARN；超过 `crit_mb` 产生 CRIT，`metrics.thresholds` 反映档位缩放值。
- [ ] C06-06 `aggressive` 档位下阈值按 ×0.85 缩放，同一内存值判定比 `normal` 更早升级。
- [ ] C06-07 `restart_on_leak=false` 时 `metrics.suggested=None`，零动作。
- [ ] C06-08 `restart_on_leak=true` 且泄漏 CRIT 时触发一次重启，冷却期内第二次触发被抑制。
- [ ] C06-09 冷启动 900s 内即使斜率超阈值也不判泄漏。
- [ ] C06-10 容器重启后样本文件保留，`started_at` 更新，斜率只用新实例样本。
- [ ] C06-11 样本文件被截断/损坏时不抛异常，探针返回正常结果并重建窗口。
- [ ] C06-12 `OOMKilled=true` 时生成证据包（`data/oom_reports/`）且通知含死亡前斜率与上限。
- [ ] C06-13 重启前快照写入 `data/memory_snapshots_<c>.json`，通知含快照路径。
- [ ] C06-14 单次 `check()` 在 200 样本窗口下耗时 < 200ms（不含 Docker HTTP 往返）。
