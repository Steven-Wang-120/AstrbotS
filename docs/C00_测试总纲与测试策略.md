# C00 · 测试总纲与测试策略（Guardian 守护系统）

> 上位规格：`B00_项目总览与需求规格.md`（唯一权威，v0.2.0）。本文定义 C 系列测试的**分层、环境矩阵、夹具、编号、判定、追溯与回归策略**；C01–C15 的具体用例均以本文为准。
> 目标平台：Arch Linux 宿主机 + Docker Compose（容器 `napcat` / `astrbot`），插件运行在 `astrbot` 容器内，经 `/var/run/docker.sock` 走 Engine HTTP API，NapCat OneBot11 HTTP `:3000` / WebUI `:6099`，默认 `dry_run=true`，自重启经宿主机 systemd 看门狗。
> 版本：v0.2.0　|　日期：2026-10-13

## 2. 测试分层

| 层 | 名称 | 运行载体 | 依赖 | 典型文件 | 判定粒度 |
| --- | --- | --- | --- | --- | --- |
| L1 | 单元测试 | 宿主/容器内 `pytest`，无事件循环依赖 | 纯函数、假对象 | C03 / C06 回归段 | 函数返回值 / 抛错类型 |
| L2 | 集成测试 | 容器内 `pytest-asyncio`，注入假 docker / 假 HTTP | 假对象 + 真 asyncio | C02 / C03 / C04 / C05 / C07 | `ProbeResult` / `Decision` / `Incident` |
| L3 | 系统测试 | 真双容器 `docker compose` + 真插件 | 真 Docker / 真 NapCat | C01 / C04 / C05 / C06 / C07 | 聊天回执 + 容器状态 + 日志 |
| L4 | 故障注入 | 真环境 + 人为破坏 | 真 Docker / 网络切断 / 杀进程 | C04 / C05 / C13 | 自愈是否在 2×间隔内发生 |
| L5 | 长稳测试 | 真环境连续运行 72h | 时间加速或真实等待 | C14 | 内存曲线 / 任务数 / 事件循环延迟 |

**分层原则**：能用 L1 断言的判定逻辑（PolicyEngine、cron 解析、线性回归、加权打分）**不得**放到 L3；能注入假对象验证的路径**不得**依赖真 Docker。L3/L4/L5 只验证"接线正确 + 端到端闭环"。

**夹具契约**（所有假对象必须与真实类型**同签名**，见 B02/B03/B04）：

```python
# tests/fixtures/fake_docker.py
class FakeDockerClient:
    """与 utils/dockerclient.DockerClient 同签名；按脚本回放响应。"""
    def __init__(self, script: dict | None = None):
        self.script = script or {}
        self.calls: list[tuple[str, tuple]] = []
    async def ping(self, timeout: float = 3.0) -> bool:
        self.calls.append(("ping", ()))
        return bool(self.script.get("ping", True))
    async def inspect(self, name: str) -> dict:
        self.calls.append(("inspect", (name,)))
        return self.script.get(f"inspect:{name}", {})
    async def stats(self, name: str) -> dict:
        self.calls.append(("stats", (name,)))
        return self.script.get(f"stats:{name}", {})
    async def restart(self, name: str, timeout: int = 10) -> None:
        self.calls.append(("restart", (name, timeout)))
    async def close(self) -> None:
        self.calls.append(("close", ()))
```

## 6. 用例编号规则与优先级定义

**编号规则**：`C{文件号}-{两位序号}`，如 `C04-07`。文件号即 C 系列文档序号（00–15）；序号在文件内**单调递增、不复用、不跳号**。跨文件引用使用全称（如 `C05-12`）。

**优先级定义**：

| 级别 | 含义 | 判定失败后果 |
| --- | --- | --- |
| P0 | 安全红线 / Gate 必过 / 阻塞验收 | 直接阻断发布；任一 P0 失败即整体不通过 |
| P1 | 核心功能主路径 | 阻断对应 Gate，需修复后复测 |
| P2 | 边界 / 异常 / 健壮性 / 可观测 | 记录缺陷，可在下个迭代修复，不阻断 Gate |

**标注规则**：每条用例必须且只能标一个优先级；安全红线（B00 §10 的 8 条）相关一律 P0。

## 7. 通过 / 失败判定总则

1. **预期结果可观测**：判定依据必须落在①函数返回值/异常、②`ProbeResult`/`Decision`/`Incident` 字段、③容器状态/文件内容、④聊天回执/日志行——四类之一，禁止"看起来正常"。
2. **判定阈值显式**：涉及时间的判定统一用"≤ N×间隔"或"在 X 秒内"，N 与 X 在用例中写明。
3. **零副作用优先**：`dry_run=true` 用例中，被测容器 `StartedAt`/`RestartCount` 必须不变；变了即失败。
4. **降级即通过**：环境不可观测（docker 不可达）时，探针返回 `UNKNOWN` + 告警 + **零动作**视为**通过**；返回 `OK` 或执行动作视为失败（B00 §10 安全红线）。
5. **不抛未捕获异常**：任何用例触发未捕获异常（含栈）即失败，即使业务结果正确。
6. **幂等性**：可重复执行的用例连续跑两次，第二次结果一致（防状态残留）。

## 8. 测试执行顺序与依赖

```
阶段 A 静态与单测（快，无外部依赖）
  A1 C03 探针框架单测        A2 C06 回归段（回归/阈值纯函数）
      │                          │
      └────────────┬─────────────┘
                   ▼
阶段 B 集成（假对象）
  B1 C02 配置/模式切换   B2 C04 容器判定（假 docker）
      │                      B3 C05 QQ 判定（假 OneBot）
      └──────────┬───────────┘
                 ▼
阶段 C 系统冒烟（真双容器，dry_run=true）
  C1 C01 安装与启动冒烟 → C2 C04/C05/C06/C07 端到端（dry_run）
                 ▼
阶段 D 真动作（dry_run=false，专用测试项目）
  D1 C04 重启闭环 → D2 C05 重登闭环 → D3 C06 泄漏重启 → D4 C07 节点恢复
                 ▼
阶段 E 故障注入（C13）→ 阶段 F 长稳（C14）
```

**依赖**：B 依赖 A 通过；C 依赖 B 通过；D 依赖 C 通过且人工确认可关闭 dry-run；E/F 依赖 D 通过。

## 9. 缺陷分级与回归策略

| 缺陷级别 | 判据 | 处理 |
| --- | --- | --- |
| S1 致命 | 违反安全红线 / 数据损坏 / 进程崩溃 | 立即阻断，P0 用例全量回归 |
| S2 严重 | 核心功能不可用 / Gate 不通过 | 阻断发布，相关文件全量回归 |
| S3 一般 | 边界异常 / 降级不彻底 | 记录，相关用例回归 + 邻近用例抽查 |
| S4 轻微 | 文案 / 可观测性 / 日志 | 记录，不阻断 |

**回归范围**：任一 S1/S2 修复后，必须回归**该文件全部 P0/P1 用例** + 受影响上游文件（如修 `core/policy.py` 需回归 C03 与依赖它的 C04/C06/C07 阈值段）。
