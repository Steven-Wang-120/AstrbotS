## 2. 前置条件

### 2.1 版本矩阵

| 组件 | 版本要求 | 检查命令 | 备注 |
| --- | --- | --- | --- |
| Arch Linux | rolling（内核 ≥ 6.x） | `uname -r` | x86_64 |
| Docker Engine | ≥ 24.0 | `docker version` | 需 API ≥ v1.44 |
| Docker Compose | v2（`docker compose` 子命令） | `docker compose version` | 不用 v1 |
| AstrBot | ≥ v4.25.1 | 容器内版本 | `@register` 需 4 参 |
| Python（宿主，可选） | ≥ 3.10 | `python --version` | 仅本地静态检查 |

### 2.2 pacman 安装命令

```bash
sudo pacman -Syu --noconfirm
sudo pacman -S --noconfirm docker docker-compose git base-devel
sudo systemctl enable --now docker
sudo systemctl status docker --no-pager
```

### 2.3 socket 权限与 docker 组

AstrBot 容器通过 `/var/run/docker.sock` 调 Docker Engine HTTP API（决策 D1），**必须**让容器内进程拥有 socket 属组 GID。

```bash
sudo groupadd -f docker
sudo usermod -aG docker "$USER"          # 宿主调试用，需重新登录
getent group docker | cut -d: -f3        # 取数字 GID，例如 989
```

> `docker.sock` 属主通常为 `root:docker`，权限 `srw-rw----`。容器内进程若非 `root` 且不在 `docker` 组，会 `Permission denied`。`group_add` 数值**必须**与宿主 `docker` 组 GID 一致。

### 2.4 时区设置

cron-lite 以**容器本地时区**解释（风险 R7），宿主与容器时区必须一致。

```bash
sudo timedatectl set-timezone Asia/Shanghai
timedatectl set-ntp true
timedatectl                              # 确认 Time zone 正确
```

容器侧由 compose 的 `TZ=Asia/Shanghai` 同步；两处都要设置。

## 3. AstrBot + NapCat 双容器部署现状

`deploy/docker-compose.yml` 完整示例（B13 只做增强，不改骨架）：

```yaml
# deploy/docker-compose.yml
name: guardian

services:
  napcat:
    image: mlikiowa/napcat-docker:latest
    container_name: napcat
    restart: unless-stopped
    environment: [TZ=Asia/Shanghai, NAPCAT_UID=1000, NAPCAT_GID=1000]
    ports: ["3000:3000", "6099:6099"]   # OneBot11 HTTP / NapCat WebUI
    volumes: [./data/napcat/config:/app/napcat/config, ./data/napcat/qq:/app/.config/QQ, ./data/napcat/plugins:/app/napcat/plugins]
    networks: [guardian_net]

  astrbot:
    image: soulter/astrbot:latest
    container_name: astrbot
    restart: unless-stopped
    depends_on: [napcat]
    environment: [TZ=Asia/Shanghai]
    ports: ["6185:6185"]                # AstrBot WebUI
    volumes: [./data/astrbot/data:/AstrBot/data, ./data/astrbot/plugins:/AstrBot/data/plugins, /var/run/docker.sock:/var/run/docker.sock]
    group_add:
      - "989"            # ← 替换为 2.3 节 getent 得到的 docker GID
    networks: [guardian_net]

networks:
  guardian_net:
    driver: bridge
```

| 项 | 说明 |
| --- | --- |
| `container_name` | 固定 `napcat` / `astrbot`，与 `containers.napcat` / `containers.astrbot` 默认值对齐 |
| `ports 3000` | OneBot11 HTTP，`qq.onebot_http_base=http://napcat:3000` 走容器网络解析 |
| `ports 6099` | NapCat WebUI，供 `webui_quick_login` 使用 |
| `restart: unless-stopped` | 宿主重启自动拉起；手动停机不被拉起 |
| `group_add` | 让容器进程可读写 docker.sock（见 2.3） |
| socket 挂载 / `depends_on` | 只挂 socket **不挂 docker CLI**；`depends_on` 只保证启动顺序，就绪由探针负责 |
| 数据挂载 | `data/` 与 `plugins/` 分开挂载，热重载不影响 data 落盘 |

## 8. main.py 最小可加载骨架

```python
# src/astrbot_plugin_guardian/main.py
from __future__ import annotations

from pathlib import Path

from astrbot.api import AstrBotConfig, logger
from astrbot.api.event import AstrMessageEvent, filter
from astrbot.api.star import Context, Star, StarTools, register

PLUGIN_NAME = "astrbot_plugin_guardian"
VERSION = "0.1.0"


@register(PLUGIN_NAME, "Guardian 守护系统", "Guardian Team", VERSION)
class GuardianPlugin(Star):
    """双模式健康守护插件（骨架：命令 + 生命周期）。"""

    def __init__(self, context: Context, config: AstrBotConfig):
        super().__init__(context)
        self.context = context
        self.config = config
        self.data_dir = self._resolve_data_dir()
        self._started = False
        logger.info(f"[guardian] data_dir = {self.data_dir}")

    def _resolve_data_dir(self) -> Path:
        # 优先 AstrBot data 目录，失败回退文件系统（D5）
        try:
            d = Path(StarTools.get_data_dir())
        except Exception as exc:  # noqa: BLE001
            logger.warning(f"[guardian] StarTools.get_data_dir 失败，回退: {exc}")
            d = Path("./data/plugin_data") / PLUGIN_NAME
        d.mkdir(parents=True, exist_ok=True)
        return d

    @filter.on_astrbot_loaded()
    async def _on_loaded(self) -> None:
        # 启动守护循环（B10 实现）
        if self._started:
            return
        if not self.config.get("enabled", True):
            logger.info("[guardian] enabled=false，跳过启动")
            return
        self._started = True
        logger.info(f"[guardian] started mode={self.config.get('mode')} "
                    f"profile={self.config.get('profile')} "
                    f"dry_run={self.config.get('dry_run')}")
        # TODO(B10): self.scheduler = Scheduler(...); await self.scheduler.start()

    @filter.command("guardian")
    async def guardian_cmd(self, event: AstrMessageEvent):
        # 命令入口：/guardian <sub>
        args = (event.message_str or "").strip().split()
        sub = args[0].lower() if args else "help"
        if sub == "help":
            yield event.plain_result(self._help_text())
            return
        if sub == "status":
            # TODO(B03/B04): 调 HealthEngine.run_once(trigger="command", scope="all")
            yield event.plain_result(
                f"Guardian v{VERSION} | mode={self.config.get('mode')} "
                f"profile={self.config.get('profile')} "
                f"dry_run={self.config.get('dry_run')}\n(健康快照待接入)")
            return
        yield event.plain_result(f"未知子命令: {sub}\n\n{self._help_text()}")

    @staticmethod
    def _help_text() -> str:
        return ("Guardian 守护系统 v0.1.0\n"
                "/guardian status            健康快照\n"
                "/guardian check [scope]     立即巡检\n"
                "/guardian mode <server|ros2> 切换模式\n"
                "/guardian profile <p>       切换档位\n"
                "/guardian restart <container> 重启容器(管理员)\n"
                "/guardian incidents [n]     最近事件\n"
                "/guardian diagnose <target> 诊断\n"
                "/guardian night [hours]     进入夜间守护\n"
                "/guardian help              本帮助\n"
                "别名: /守护")

    async def terminate(self) -> None:
        # 清理：严格取消任务，防止热重载残留（风险 R10）
        # TODO(B10): await self.scheduler.stop(); await self.engine.close()
        self._started = False
        logger.info("[guardian] terminated")
```

**自检点**：`@register` 四参齐全；`__init__(self, context, config)` 签名正确；`terminate` 存在且幂等；消息只经 `yield event.plain_result(...)` 返回。

## 9. 本地开发与热重载流程

1. 宿主编辑 `AstrbotS/src/astrbot_plugin_guardian/`。
2. 同步到容器插件路径（compose 已把 `./data/astrbot/plugins` 挂到 `/AstrBot/data/plugins`），或直接绑定挂载开发：
   ```bash
   cp -r src/astrbot_plugin_guardian deploy/data/astrbot/plugins/
   ```
3. WebUI（`http://<host>:6185`）→ 插件管理 → `astrbot_plugin_guardian` → **重载插件**。
4. 观察日志：`docker logs -f --tail=200 astrbot | grep -i guardian`。
5. QQ 发 `/guardian help` 验证命令已注册；改 `_conf_schema.json` 后需**重载插件**才能在 WebUI 看到新键（见 B02 生效矩阵）。

**注意**：重载会调用旧实例 `terminate()`。若未取消定时任务将出现双份巡检（R10），骨架期即须保证 `terminate` 幂等。

## 10. 依赖安装隔离说明

- 依赖**只声明在插件 `requirements.txt`**，由 AstrBot 加载插件时安装到其虚拟环境，不污染系统 Python。
- 不要 `pip install` 到容器系统环境；不要改 AstrBot 自身依赖。
- `requirements.txt` 变更后需重载插件或重启容器触发重装：`docker compose -f deploy/docker-compose.yml restart astrbot`；离线环境可预置 wheel（B13）。

## 11. 常见坑

| # | 现象 | 根因 | 处置 |
| --- | --- | --- | --- |
| 1 | 探针报 `Permission denied` | `group_add` GID 与宿主 docker 组不一致 | 重新 `getent` 取值并更新 compose |
| 2 | `Name or service not known` | 未在同一 network | 两服务都在 `guardian_net`，用容器名互访 |
| 3 | cron 在错误时间触发 | 宿主/容器时区不一致 | 双端 `TZ` + `timedatectl` |
| 4 | 容器内 `docker: command not found` | 骨架不装 CLI（D1） | 走 socket HTTP；仅 `use_cli_fallback=true` 才需 CLI |
| 5 | 重载后重复巡检 | 旧定时任务未取消 | `terminate()` 严格 cancel + 幂等启动（R10） |
| 6 | 数据落在插件目录，更新即丢 | 误用插件目录写文件 | 统一走 `StarTools.get_data_dir()`（D5） |
| 7 | `@register` 报缺参 | AstrBot ≥4.25.1 需 4 参 | name/desc/author/version 全给 |
| 8 | 使用 `requests` 阻塞事件循环 | 违反 D9 | 一律 `aiohttp` |
